国庆第一天刚面完Minimax的Agent开发岗，面试强度非常大，在空调房里都给我面出汗了，顺便分享一下Agent方向的面试思路。

我之前在字节工作，面试里提到的很多项目细节都是我实际参与落地的。Minimax正常的技术面一般是两轮，但我之前的base薪资已经有37K，本科毕业两年这个薪资水平算比较高的，所以后面又加了一轮CTO面。

技术一面、技术二面和CTO面问的问题方向都不太一样，但有一个核心共同点：判断我到底有没有真正从零到一做过Agent系统。其实现在Agent方向的面试都很看重项目真实性，普通的实习生或者业务线开发，很少会在实际工程里完整覆盖Agent全链路、效果评估与策略迭代这些深度工程化工作。

## 技术一面：深挖项目真实性与技术细节
一上来面试官就让我完整讲透Agent的执行链路：用户输入需求以后，系统怎么识别意图？怎么拆解任务？多个步骤的执行优先级怎么定？什么时候调用大模型，什么时候调用工具？不同类型的任务又怎么匹配对应的模型？

紧接着就开始深挖项目细节：
- Skill模块是怎么设计的？
- 长短期记忆怎么区分？什么信息会进入长期记忆？
- 记忆库内容越存越多、数据膨胀该怎么解决？
- 上下文窗口是多少？实际业务场景里会用到多少？
- 什么时候触发上下文压缩？阈值怎么定？压缩以后丢失重要信息怎么办？

后面甚至直接聊到成本核算：不同业务场景怎么选型模型？如果让Agent写1000行代码，大概消耗多少Token？百万Token的计费逻辑是怎样的？单次任务的成本大概是多少？

所以技术一面给我最大的感受是：面试官不是在听你背了多少概念，而是在判断你的项目是不是真的在生产环境跑过。你说做了上下文压缩，他就会问你为什么要压缩、什么时候触发、效果怎么评估；你说用了记忆模块，他会问存储方式、召回逻辑、数据膨胀的解决方案；你说做了工具调用，他就问调用失败怎么处理、线上的兜底机制是什么。

如果你的项目只是跟着教程跑了一个Demo，没有真正考虑过全链路、记忆管理、上下文、成本和异常处理，一面很容易就被问穿。所以一面的本质，就是考察项目的真实性和技术细节的扎实度。

## 技术二面：考察架构设计与工程化能力
到了技术二面，考察方向明显转变。一面是验证“项目是不是你做的”，二面则是考察：如果真给你一个项目，你能不能从0到1把企业级Agent设计出来。

比如面试官会问：设计一个企业级Agent，整个系统该怎么拆分？用户请求进来怎么识别任务类型？怎么判断是简单任务还是复杂任务？复杂任务怎么拆解成子任务（Subtask）？又怎么生成可执行的计划？

执行层面的问题也非常细：
- 执行完怎么判断当前步骤是成功还是失败？
- 工具调用超时了怎么办？什么时候重试（Retry），什么时候需要重新规划？
- 任务执行到一半服务挂了，怎么做状态恢复？

还问到了代码Agent（Coding Agent）的设计，应该是对应Minimax的代码类产品。核心问题是：如果让Agent理解一个大型代码仓库，不可能把几十万行代码全部塞进上下文，那怎么结合向量检索、关键词搜索、AST语法分析和调用链分析，构建出当前任务需要的代码上下文？

除此之外还有工具系统的设计：工具怎么注册？Schema怎么定义？哪些工具是只读权限，哪些可以执行写操作？高风险操作怎么做权限管控？以及主流代码Agent产品、Claude Code Assist这类工具的方案对比与使用体验。

所以二面真正考察的是：这个Agent如果明天就要交付给企业使用，你能不能保证它稳定运行？多人并发使用会不会出问题？任务失败能不能自动恢复？工具有没有明确的权限边界？Token成本能不能控制住？模型输出异常怎么兜底？版本迭代之后怎么量化证明效果提升了？

我觉得大部分人学Agent，只解决了“怎么让它跑起来”的问题，但生产环境、大厂真正需要解决的，是“怎么让它长期稳定地跑”。所以二面本质上考的是架构能力和工程化思维，而不是你会不会用某个框架。这也是很多公司偏好招大厂背景的人的原因——切换到Agent赛道之后，模型虽然是新的，但高并发、容错、权限监控、成本控制这些经典工程问题依然存在。

## CTO面：判断个人价值与行业认知
到了第三轮CTO面，技术问题就很少了，核心是考察个人的职业选择、行业认知和独当一面的能力。

主要问的问题包括：为什么选择Agent方向？对这个方向的未来怎么看？是因为近几年风口才做，还是准备长期深耕？有没有定期关注行业AI动态？有没有用过最新的Claude Opus、GPT系列大模型？对于全天候Agent有什么看法？觉得怎么学习才不会在AI时代被淘汰？

最后还问到了核心问题：你和其他候选人的差异是什么？
我的回答是：我不只是会调模型API，也有完整的工程落地和真实业务经验；而且在2025年Agent还没有现在这么火的时候，就已经开始系统学习并落地相关项目了。

面试官又追问：那你能给公司创造什么价值？我就直接拿之前在字节的一个落地项目展开，讲我解决了什么核心问题，这些经验如果进入Minimax，可以怎么迁移到他们的业务里；如果让我负责这个方向，我准备怎么推进。

最后甚至问到：如果入职以后给你配一个运营，让你单独负责一个业务线的Agent，有没有信心把它做到行业头部。

所以CTO面给我的感觉非常直接：想拿高薪，就得证明自己有独当一面的能力。大厂里更看重主动性，需要的不是等着别人分配任务的执行者，而是能主动发现问题、推动项目、承担负责人职责，甚至独立负责一个方向、最终拿到结果的人。

## 面试总结与行业观察
仔细复盘这次Minimax的面试，三轮考察的侧重点非常清晰：
1. **技术一面**：验证项目真实性，重点考察Agent执行链路、任务拆解、Skill设计、记忆管理、上下文处理、模型选型、Token成本
2. **技术二面**：考察工程架构与落地能力，重点是稳定性、任务恢复、工具权限、成本控制、效果评测，以及Agent的可上线性
3. **CTO面**：判断个人价值与AI认知，包括做Agent的动机、和其他候选人的差异，以及能给公司创造的核心价值

现在Agent开发已经进入了新的阶段，只会调用大模型API、跟着教程做简单Demo，已经完全应付不了大厂的面试了。我接触过近百份真实的大模型面试录音，涵盖通义千问、腾讯、豆包以及不少AI创业公司的面试，一个很明显的趋势是：单纯考察Transformer、NLP基础的问题越来越少，反而越来越侧重底层的真实业务场景。

所以大家准备面试的时候，落地指标、实际业务场景一定要介绍得非常详细。如果你现在准备转Agent方向，一定要把项目里的设计思路、技术选型、性能优化、异常处理、成本控制和效果评估讲透。因为面试官真正想知道的，不是你会不会做Agent，而是这个Agent交给你之后，你能不能把它真正做上线。
