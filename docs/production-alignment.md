# 与真实产线的对齐

本文记录本工程的哪些设计来自**真实在跑的产线**，而不是我凭空定的。
依据两类原始资料（均为作者本地工作区资料，未随本仓库分发）：

1. `AI漫剧制作工作流执行手册.md`（六阶段流程、通道与成本、各阶段交付标准、严禁事项）
2. `Seedance2.0终剪提示词.md`（《我在仙界当了一天大弟子》的真实终剪交付物格式）

---

## 1. 视频提示词的硬结构（本次最大的修正）

**问题**：原来的系统提示词是我自己编的一句话——「按冻结槽位编号引用参考图，标明镜头与时间区间」。
真实交付物的结构严格得多，缺一项都会直接反映在成片质量上。

**现在的结构**（`app/core/prompts.py` 的 `video_plan_create`）：

| 段落 | 要求 | 手册出处 |
|---|---|---|
| 参考图定义段 | 逐张写「将参考图一中的…定义为场景：…」；编号与冻结槽位顺序一致，**一张都不能省，禁止合并缩写与「同上」** | §6.2 |
| 视角段 | 写明全片视角与不变量（一镜到底、不切镜） | §4.0 |
| 分镜段 | `镜头N（起-止秒）：…`，N 从 1 连续；**时间加总必须等于片段时长**；单镜头只留一种运镜 | §4.0 |
| 环境音段 | 以「环境音：」开头，写明是否生成背景音乐 | §4.1 |
| 收尾句 | 「…**无字幕，避免生成任何文字或字幕**」 | §6.2 |

**校验层**：`app/services/prompt_rules.py` 把上面这些做成 lint：

- 缺分镜标签 / 编号不连续 / 时间加总不符 / 缺参考图编号 / 参考图覆盖不全 / 缺「无字幕」/ 出现严禁措辞 / 出现旧体系术语
- **定位是 lint 不是闸门**——手册的经验是「判一版提示词至少要跑 2 发」，所以不拦死用户，
  但问题会当场挂在方案节点上，前端抽屉用警示框列出，避免拿钱试错。

## 2. 提交前校验（PRD §7.1 的落地）

来自手册 §3.1 / §4.0 的档位规格，写在 `media_ops._assert_video_request`：

| 项 | 规则 |
|---|---|
| 时长 | mini / fast **4–15s**；2.5 **4–30s**。>15s 的片段若选了 mini，**提交前报错并提示改档**，不静默截断 |
| 参考图 | 每片段 **≤ 9 张**，超限报错并提示调整，**不自动丢图** |

这两条都在**调用模型之前**拦截——被拦下不产生 attempt，也就不产生费用。

## 3. 图片阶段的分工

手册 §2.2 / §5 明确：

- **k（Krea 2）** 出纯场景、载具、道具（文生图）
- **q（Qwen-Image-Edit）** 做图生图：**以归档立绘派生三视图 / 面部特写 / 换装**；
  「凡画面里要出现已归档角色的脸与造型，一律走 q + 归档图垫底」——
  **k 重出会换脸并漂向写实**
- 面部特写与服装解耦（只锁脸，可跨服装复用）；三视图含服装与体型，按服装分别出

本工程的 `image_derive` 已按此实现：**以当次选中的立绘为源图走图生图**，
模板固定、各生成 1 张、不覆盖旧结果。这条与手册的结论一致，不是巧合——PRD §5.5 本来就是从这条产线经验来的。

## 4. 命名规范

手册 §2.2 的静态资源命名与 `app/services/naming.py` 的解析规则一致：
`00人物-<名>[-<服装>]-三视图` / `01场景-<名>` / `02道具-<名>` / `00兽设-<名>` / `00载具-<名>`，
`_候选-` 前缀跳过。手册里 `00参考-<镜号>-<名>` 是 POV/站位锚点，本版按 PRD 不收。

## 5. 已知硬约束（本版只记录，未实现规避）

- **官方两道拦截**（手册 §3.2）：① 真人识别——参考图里检测到真人脸，**提交阶段返回 400、不扣费**；
  ② 版权比对。**真人写实项目过不了①**，手册给的出路是走中转 liaobots。
  本版 PRD 明确「只接火山方舟官方接口」，因此**没有接入中转**，也没有做项目画风标记；
  真人写实项目在当前版本会走不通视频阶段。这是一条产品决策，需要时再定。
- **m（本地草稿层）** 本版未接入：手册的 m 是本地 ComfyUI 的免费草稿层，正片一律用官方 s-mini。
  本版直接走 s，省掉草稿环节会多花钱，但对 Demo 而言少一整套本地依赖。
- **参考视频**（≤3 段）本版未支持；模型配置里只登记了参考图上限 9 张。

## 6. 还没做的对齐（诚实列出）

| 手册要求 | 现状 |
|---|---|
| 阶段门禁「每一阶段产出后必须用户确认」 | 有确认动作（清单确认、选版），但没有强制门禁状态机 |
| 每 clip 最多改 2 次的额度控制 | 未实现 |
| `镜头N（起-止秒）` 之外，POV 项目的一系列专用写法 | 只在系统提示词里给了通用结构，未按项目类型分派 |
| 单条 clip 至多一人开口 | 未做校验 |
| A/B 对比钉同一个 seed | 支持固定 seed（此时数量强制为 1），但没有 A/B 对比工作流 |
| 「判一版至少跑 2 发」的批量抽卡约定 | 支持 N 次抽卡，但没有「至少 2 发」的提示 |
| `经验教训.md`（80KB，手册列为最优先） | 本次只读了手册与终剪交付物，复盘文档尚未逐条吸收 |
