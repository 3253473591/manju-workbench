## 0. 一句话与目标用户

**一个受控的 AI 漫剧生产链路**：从一句原始想法到成片，五环节由 Agent 完成，人只在**付费点**和**审批**上做决定；每一步可追金额、可归因、可回滚。

- 目标用户：2–5 人的小团队 / 个人创作者（非企业级、单机部署、零 key 可跑）；
- 交付定位：求职作品集 —— 重点不是"功能最多"，而是**流程不可绕过、结果可验证**。

## 1. 用户旅程（演示与验收共用的主线）

| 步骤 | 用户动作 | 系统给的确定性 |
|---|---|---|
| 1 | 打开已有剧集 | 真实成片、真实成本都在库里，不是假数据 |
| 2 | 跑 S1–S3 | 五环节一条路径；S3 直接写进分镜表 |
| 3 | 跑 S5 → 出人物卡 | 人物卡可出图并进入资产库 |
| 4 | 给第二集挑第一集的图 | 资产项目级复用，不复制文件 |
| 5 | 点「生成…」→ 看预估 → 确认付费 | 确认前零计费；确认后按 token 记账 |
| 6 | 看质检与执行时间线 | 判不了就 `unknown`，不装懂；每步有耗时 |
| 7 | 打回 → 重发 → 回滚 | 版本链完整；回滚不花钱 |
| 8 | 删一张在用素材 | 409 拦截，并列出引用它的片段与槽位 |
| 9 | 看成本台账 / 管理面 | 按模型/集/片段/天看钱；通道可一键停用 |

## 3. 功能详述

### F1 项目与多集
- 一个项目下多集；片段序号按集独立，成本可按集聚合；
- 集可新增、**重排**、删除；删除**不重编号**（留洞是刻意的），有付费产物的集/片段**禁止删除**；
- 所有资产（成片、人物图）**项目级**共享：同一张图被多集引用时不复制文件。

### F2 五环节生成
- S1 作用于项目，S2/S3 作用于集，S4 作用于片段，S5 作用于项目；
- 每步的产物**落库并写回**对应对象，且在对话里能看到"这一步用了哪些规则、耗了多少 token"；
- S3 会依据剧本**新建片段**；该集已有片段时拒绝重跑（避免冲掉已出的片）；
- S2 在已有分镜的集上同样拒绝（避免剧情与分镜静默不一致）。

### F3 出图
- S5 产出人物卡后可直接出图；产物进入项目资产库，可被槽位引用；
- mock 通道下**指向已有素材**（不复制文件、零成本）；真通道走 OpenAI Images 兼容服务；
- 返回值明确区分"**这次是不是真出图**"与"是否命中了已有资产"。

### F4 资产与槽位
- 每个片段有若干参考槽位，可指派项目内任意图片；
- 删除资产前检查引用：被槽位或某次 take 引用时**拒绝删除**，并列出来源；
- 物理文件默认保留（素材是用户的原始资产）；仅对系统生成的派生文件支持"连文件删"。

### F5 出片与付费点
- 两段式：**提交（不产生计费）** → 看预估金额与 token → **确认付费**；
- 确认后进入执行：入仓、补宽高/时长/海报、质检、决策；
- 同项目视频任务串行；重复提交同一请求**不会重复扣费**；
- 失败可按规则自动重试（仅"自动模式"），默认模式失败即停、等人处理。

### F6 质检
- 动线检测（画面是否真的在动）+ 内容级判据（画面是否满足验收点）；
- 三态结论：`pass` / `fail` / `unknown`；**`unknown` 不等于通过**，片段留在待审；
- 能力缺失（无动线脚本、无视觉模型）时**降级**并在结论里标注；
- 没有可机检验收点的片段，走"无判据"分支放行，同时留下可追溯说明。

### F7 审批与版本链
- 「打回」把片段置为 rejected；「重发」以打回为前置，生成新 take；
- 每次生成都是 append-only 的 revision，可 diff 两版、可回滚到任意有产物的历史版；
- 回滚**不写新 revision、不产生费用**；片段回到待审状态。

### F8 成本台账
- 四个口径：按模型、按集、按片段、按天；
- 金额 = 上游真实用量 × 配置单价；视频按 token 计费（不是按秒）；
- 项目日预算到顶后，新提交**在提交前**被拒绝（不是在执行中失败）。

### F9 Skill 维护（知识层）
- Skill 有版本与状态；新建版本后必须**试跑**才能发布，发布后旧版自动转为被取代；
- 试跑按"注入关系"选目标（不是猜 stage），只组装上下文、不调用上游、不花钱；
- 支持回滚到历史版本、停用；**admin 能改规则，改不了内容**。

### F10 管理面
- 展示文本/视觉/视频/出图四条通道的配置与真假；提供"真打一次上游"的连通性检查；
- **运行时止血开关**：管理员可停用任一通道（必须写原因），停用后所有调用点在**花钱之前**被拒；
- 开关状态存共享存储、多副本一致，面板显示"谁、为什么、什么时候"停的。

### F11 实时事件
- 任务状态、片段、成本变化通过 SSE 推送到前端；断线可用 `Last-Event-ID` 续传；
- 缓冲缺口时发 `resync` 让前端全量刷新；
- 多副本部署时，别的副本产生的事件也能在 ≤0.5 秒内补上（进程内直推 + 日志轮询）。

### F12 自检与彩排
- **开录前自检**：机器验证"迁移到 head / 演示项目 active / 有 review 片段 / 有可回滚 take / 有跨集资产 / Skill 生效 / 通道全部启用 / 媒体目录可读"等 16 项，阻断项直接指名；
- **彩排**：按录屏顺序真打 10 拍接口（含管理员面），非破坏性（用临时片段演打回/重发），约 9 秒；
- 演示录屏与逐拍执行卡随仓库提供。

## 4. Agent 防御性设计（把"模型不可靠"当前提）

> 章节定位：模型会幻觉、会包信封、会漏字段、会回退；上游会限流、会超时、会静默失败；
> 人会手滑、会重复点击；配置会漂移。以下防线全部在**服务端**生效，不依赖 Agent 自觉或前端校验。

### 4.1 威胁模型

| 威胁 | 典型表现 | 防线 |
|---|---|---|
| 模型输出不合契约 | 包里多一层信封、缺必填字段、类型错 | 输出契约进 prompt + 严格校验 + 拒绝而非猜测 |
| 坏数据入库 | 分镜不闭合、台词没进提示词、槽位断号 | 写入时域不变量，违规即拒 |
| 重复提交 | 双击、重试、网络重放 | 幂等指纹（含模式）+ 唯一键 |
| 超预算 / 烧钱 | 预估失真、重试累积、项目日超支 | 调用前预算检查 + 重试累计 + 日预算闸 |
| 上游故障 / 限流 | 401、429、5xx、超时 | 错误分类 + 可重试标记 + 停止条件 |
| 通道混用 / 配错 | 拿视频通道做视觉、key 配错 | 通道配置独立（文本/视觉、视频、出图各自配） + 启动即校验 + 连通性检查 |
| 静默降级 | 质检能力缺失却当通过 | 三态结论 + 降级标记 |
| 提示词注入 | 剧本/参考文本里夹带指令 | 外部内容一律当数据；模型无工具执行权 |
| 引用悬空 | 删素材导致槽位指向空 | 被引用即禁删 + 引用方列表 |
| 删除丢账 | 删集/删片段把已付的钱从台账带走 | 有付费产物即禁删 |
| 无人值守空转 | 归因不出还无限重试 | 重试上限 + 归因不出即转人工 |
| 配置漂移 | 设置了但没代码读、重启后才生效 | 启动校验 + 配置项审计（规划中） |

### 4.2 七道防线

| # | 防线 | 机制 | 用户可见表现 |
|---|---|---|---|
| 1 | **输出契约** | 每次调用把结构化 schema 原文写进 prompt；校验严格禁止额外字段；模型返回信封时明确报错 | 失败时 422 并指出哪个字段不符 |
| 2 | **域不变量** | 分镜必须闭合、台词必须逐字进入提示词、槽位必须连续、验收点 id 唯一、成本必须等于单价×数量、状态迁移必须在表内 | 坏数据根本写不进去；冲突返回 409/422 |
| 3 | **成本控制** | 默认模式在付费点停；调用前查预算；重试累计成本；项目日预算到顶直接拒 | 确认前零计费；超预算时给出已花/上限 |
| 4 | **幂等与串行** | 同 key 同请求返回原任务；同项目视频任务串行；写操作带版本条件 | 重复点击不会二次扣费 |
| 5 | **失败归因与止损** | 失败先归因；有可执行修法才重试（≤3 次）；归因不出立刻转人工 | 任务终态为"已升级"，附原因 |
| 6 | **通道隔离与止血** | 文本/视觉、视频、出图三套配置与调用点分离；管理员可运行时停用 | 停用后调用前即 503，并显示原因 |
| 7 | **审计与回滚** | append-only 版本、执行时间线、成本台账、SSE 事件 | 每一分钱、每一次失败都能追溯 |

### 4.3 失败语义（fail-closed 清单）

| 场景 | 系统行为 |
|---|---|
| 模型输出不合契约 | 拒绝，不修复、不猜 |
| 动线/视觉能力缺失 | 结论标为 unknown 并标记降级，片段留审 |
| 视觉证据不足 | unknown，不判 pass |
| 上游可重试错误 | 在自动模式下重试；默认模式失败即停 |
| 上游不可重试错误 | 直接失败，不空转 |
| 预算不足 | 调用前暂停，不产生 revision |
| 归因不出可执行修法 | 一次即转人工 |
| 引用的资产/内容受保护 | 409 拒绝并说明引用方 |
| 通道被停用 | 调用前 503，带原因与停用时间 |

### 4.4 可验证性

| 手段 | 规模/内容 |
|---|---|
| 自动化测试 | 564 条（域不变量、协议、并发、授权、业务逻辑、多集） |
| 对抗性审计 | 四轮、**16 个真实缺陷**，每个都有回归用例与修法记录 |
| 契约回归 | 20 条 golden 用例，只断言契约不断言措辞 |
| 演示自证 | 16 项开录自检 + 9 拍彩排 + 录屏 |
| 真实上游实测 | 文本/视觉/视频/出图四条通道均有真机数字（延迟、token、金额） |

### 5.2 逐个优缺点

**novel-to-script-team**
- 优：流程最完整；17 个角色边界清晰；24 篇方法论（心理学 40KB、摄影 31KB、Seedance 33KB）；可恢复 agent 状态；
- 缺：全靠 Agent 自觉，跳过审核无人拦；无 DB/UI/队列；零 pytest；乱码与称呼检查靠两条 grep。

**ManjuForge**
- 优：把"30 集不崩"做成了机制 —— 7 个记忆文件 + 3 引擎；**检查器是真代码**（退出码、红黄绿、每条报错给"哪两个文件矛盾 + 怎么修"）；47 条自测防误报；adapter 四步确认；MIT-0；
- 缺：文档即数据库（所以需要 22 项检查兜底）；检查的是生成前文档而非产物；44KB 单 SKILL.md 上下文成本高；无 CI 集成。

**wind-comic**
- 优：产品级广度与工程信号（8 Agent、12 引擎竞速、Yjs 实时协作、导演控片台、帧级检查 + 分段重拍、TTS/口型、模板市场、成本归因 + 四维发布门）；6635 测试 + Playwright + CI 镜像；
- 优（更值得学）：**复盘文化** —— 发布说明逐条讲自己的事故（"设置没有读者"、"引擎请求静默发错、回退到别的引擎"），并给"未验证声明"和可复跑探针；
- 缺：文档膨胀（VERSIONS 1MB、ROADMAP 219KB）；12+ 引擎带来配置漂移与维护成本（其事故正是来源）；学习/上手门槛高。

**腾讯云创意工坊（文章）**
- 优：把行业痛点讲清楚（工具链割裂、模型管理混乱、门槛高、分辨率限制、协作成本）；多模型整合、视频理解→分镜、4K/2K 超分、抢占锁 + 超时踢出的协作方案；
- 缺：闭源、无法评估；云资源绑定；重平台轻"钱与审计"的可见性（文章层面未展开）。

### 5.4 不借鉴清单

- 不做"文档即状态"：状态必须有约束与审计，不接受"靠检查器兜底"；
- 不做 44KB 单文件 Prompt：知识分批、按节注入、版本化发布；
- 不做 12+ 引擎矩阵：三通道、可替换、可停用足够；
- 不做 VERSIONS 级文档膨胀：README 保持 ≤200 行，细节分层进开发文档。

## 6. 范围外（明确不做，及原因）

| 不做 | 原因 |
|---|---|
| 4K/2K 视频超分 | 属于媒体处理管线，与"受控生产链路"无关，且成本/算力不在 demo 范围 |
| 多模型画廊（7+ 模型自由切换） | 通道抽象已够；模型矩阵会带来配置漂移（见 wind-comic 事故） |
| 视频理解（视频→分镜） | 独立能力，与 S1–S5 的生成方向相反 |
| 实时多人编辑（CRDT） | 2–5 人规模用 presence + 乐观锁 + 项目串行已够；CRDT 是另一个一致性问题 |
| TTS / 口型 / 时间线剪辑 | 属于后期制作，超出"分镜→成片"的 demo 边界 |
| 企业级多租户计费 | 求职 demo，不做支付与发票 |

## 8. 结语：我们的位置

四个参照分别把"**分工**"（novel-to-script-team）、"**一致性检查**"（ManjuForge）、"**产品厚度**"（wind-comic）、"**平台资源**"（腾讯）做到极致。

本项目选择第四种定位：**把流程做成不可绕过的控制面**。

> 广度上不与它们比；但"每条生成能追到钱、每次失败有归因、坏数据进不了库"这三件事，
> 由账单、测试与审计记录证明，而不是由文档承诺。
