# 代码审查与修复记录（2026-10-19）

先完整阅读了《PRD v0.3》，按单机、2–5 人、Mock 为主的求职 Demo 审查 API、任务执行、数据库、前端和配置。全员可读他人项目、admin 对内容只读、没有多租户，以及 README 已声明未实现的功能，均按项目设计处理。

## 已修复

| 影响 | 触发条件与原有问题 | 修复位置与结果 |
|---|---|---|
| 高：越权写入 | admin 成为项目成员或所有者后，可以写项目内容；也能创建项目，与 PRD 权限矩阵冲突 | `deps.py`、`api/auth.py`、`api/projects.py`：admin 始终只读内容，仅 lead 创建项目，能力标志与服务端一致 |
| 高：并发覆盖 | 两个请求通过同一 `If-Match` 校验后，后提交者覆盖先提交者 | `models.py`、`main.py`：项目、集、片段更新在数据库比较旧 version，竞争失败返回 412；保留现有版本递增方式 |
| 高：项目队列串行失效 | 多个待确认任务分别确认，或同时提交任务，绕过“每项目一个 queued/running 视频任务” | `jobs.py`、`db.py`：确认、重试与提交共用项目锁；使用 READ COMMITTED 避免锁后读旧快照和空范围间隙锁 |
| 高：幂等语义错误 | 相同幂等键切换 default/auto，或并发首次提交，发生错误重放或重复提交 | `api/jobs_api.py`、`jobs.py`：模式进入请求指纹；拿到项目锁后再次查幂等键；冲突回读也校验指纹 |
| 高：预算检查过晚 | 预算尚有少量余额，但不足支付下一次生成，仍调用 provider | `jobs.py`：预计成本超过剩余额度时先转 `paused_budget`，不调用 provider；实际意外超支仍保留账目 |
| 中：任务无限重跑或卡住 | 目标被删除、产物文件缺失、状态转换或执行异常，事务回滚后任务重新变成 queued，或留在 running | `jobs.py`：失败进入终态；后处理使用保存点，保留 provider 已返回的费用与 revision；修正 draft/rejected 生成的状态路径 |
| 中：取消覆盖完成状态 | 请求持有旧任务对象，在 worker 完成后写入 cancelled | `jobs.py`：修改任务状态前加行锁刷新状态；排队中的重复 retry 不再消耗次数 |
| 中：验证被绕过 | S3 的镜头/台词/验收内容只是任意字典；S4 可以把缺少有效分镜的片段推进 prompted | `steps.py`：嵌套输出使用已有类型，写入 S4 前复用片段不变量校验，非法 provider 输出返回明确错误 |
| 中：错误输入触发 500 | 非字符串传入字符串预处理器、不可空字段显式 null、无效或极端日期、签名正确但缺少必要声明的 JWT | `schemas.py`、`security.py`、内容/成本接口：分别返回 422 或 401；正常最大日期可查询 |
| 中：资源边界缺失 | 无 Content-Length 的请求绕过体积/类型限制；慢请求、数据库通信、浏览器 fetch、素材子进程缺少超时 | `main.py` 实测流量限制 2 MiB、读体 30 秒；数据库连接 5 秒、读写 30 秒；前端请求 30 秒；ffprobe 15 秒、ffmpeg 60 秒并保留导入降级行为 |
| 中：内存持续增长 | 登录失败键随 IP/邮箱组合持续累积，旧键不回收 | `api/auth.py`：过期回收、最多 4096 个键、每键次数有界；共享计数加线程锁 |
| 中：停机与后台线程脱节 | 取消 `to_thread` 的外层协程不会停止同步线程，连接池先关闭，worker 还在执行 | `main.py`：停止领取新任务，等待当前任务退出后释放引擎；每次 drain 只执行一个任务 |
| 中：新增与注册竞争 | 同集并发新增片段可选中相同序号；并发注册同一邮箱可变成数据库异常 | `api/episodes.py` 父行锁串行分配序号，达到末号时复用空根片段槽位；`api/auth.py` 将唯一键竞争转换为 409 |
| 低：界面与状态不一致 | 归档第二次失败；任务完成后仍可确认，成本与片段不刷新，已提交预算仍能改显示值 | 归档幂等；前端按任务状态禁用确认、锁定已提交预算并刷新相关查询，非 JSON 错误响应有明确提示 |

确认与 worker 的锁顺序也做了专项回归：修复过程中复现过 MySQL 1213 死锁，已调整为先 job、后 project，避免确认持有项目锁、worker 持有任务锁时互等。该问题没有作为原始代码缺陷重复计数。

## 按 Demo 定位保留的限制

| 限制 | 影响与后续边界 |
|---|---|
| worker 在一个数据库事务中完成 Mock 调用及质检，任务输入读取片段当前内容 | 慢执行期间状态写入可能等待，确认预览不是不可变快照；尚无真实付费 provider。接入真实服务前需要短事务领取、心跳、输入快照、上游幂等与外部副作用对账；本次不宣称解决进程崩溃后的恰好一次计费 |
| 删除片段后，项目成本查询不再包含该片段历史 revision | 静态确认 `api/projects.py::project_cost` 按现存 clip ID 聚合。账目行仍在，但看板会少计；固定素材 Mock 演示暂保留。用于真实计费前应增加稳定的项目账目归属，不能把当前看板当财务台账 |
| 编辑锁是提示性锁，获取/释放仍有竞争窗口 | 数据更新已有数据库版本比较保护；2–5 人协作提示可暂容忍偶发失准，未增加分布式锁设施 |
| `res=final` 等参数尚未接入独立真实生成分支 | 当前只回放 Mock 草稿。真实精修、SSE、Skill 写接口、provider 配置面板仍按 README 的未实现范围处理 |
| 登录限流是有界进程内缓存，重启会清空 | 适用于当前单机 Demo；没有加入 Redis 或生产级反滥用系统 |
