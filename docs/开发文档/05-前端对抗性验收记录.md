## 3. 撞出来的缺陷（都已修）

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | **《师尊别砍我系统》在界面上根本进不去** | 项目只取 `items.find(active) ?? items[0]`，没有切换器；库里两个 active，真实的那个排在最后 —— 83 个资产、13 个片段、31 条 revision 在 UI 里全不可见，README 演示脚本"切到《铜柱之下》"也无处可点 | 头部加项目下拉（`projectId` 状态），新建项目后自动选中 |
| 2 | **S4 的片段下拉白底白字，"运行 S4"被挤出视口** | 只有 `.mj-head-right select` / `.mj-slots select` 有样式，`.mj-actions` 里的 `<select>` 是 UA 白底 + 继承的白字；下拉的 max-content 又把 `.mj-stage` 的网格轨道顶到 473px，1440 下按钮右沿到 x=1565，整页横向溢出 125px、头部被裁 | `.mj-shell select` 统一暗色；`.mj-stage{grid-template-columns:minmax(0,1fr);min-width:0}`；`.mj-actions select{flex:1 1 0;min-width:0}`。修后下拉 228×30、按钮右沿 1401、`scrollWidth == clientWidth` |
| 3 | **通过/打回遇 412 静默失败** | `Row` 的 approve/reject 没有 `onError`、也不渲染错误；另一处把 version 顶上去后点"打回"，网络里是 412，界面一动不动 | 行内渲染 `failure.message`（红字），与后端"版本已过期"对齐 |
| 4 | **S1/S2 之后头部一直显示旧值** | 写操作只失效 `clips/cost/revisions`，SSE 也只失效这几类；S1 改了 `genre/tone`、S2/S3 改了 `episode.status`，头部要手动刷新才对 | 统一 `refresh()`：`projects/episodes/clips/projectClips/cost/jobs/revisions` 全失效，写操作与 SSE 共用 |
| 5 | **付费点没有"取消"** | `api.cancel` 早就定义，UI 从没调用；弹窗底部却写着"取消后 job 为 cancelled" | 非终态时显示"取消"按钮 |
| 6 | **重发弹窗里看不到版本链** | `revisions` 查询只在 job 终态后启用，而演示脚本写的是"重发…→ 弹窗里看版本链，回滚到上一版" | `mode === "reroll"` 时直接启用；重发前就能对比/回滚 |
| 7 | **SSE 断了只改文案，没有轮询** | 状态栏写"轮询兜底"，但 clips/cost 等查询没有 `refetchInterval`，唯一定时拉取的是 job 弹窗 | `offline` 时每 5s 全量 invalidate，恢复 `live` 自动停 |
| 8 | **失败提示是绿色的** | 付费点 / Skill 维护 / 资产库 / 槽位保存的失败信息都走 `.mj-msg`（绿），"参数超出允许范围""该资产正被引用"看起来像成功 | 失败走 `.mj-error`，成功才走 `.mj-msg` |
| 9 | **镜头墙把视频产物当图片渲染** | `<img src="/assets/{id}/file?thumb=1">`；没有海报时后端原样回 `video/mp4`，浏览器给破图、图片区塌陷 | 加 `WallThumb`：`onError` 退回"视频产物"占位 |
| 10 | **资产库有海报也不显示** | 视频一律渲染"视频 · 宽×高"占位，连标着"有海报"的 19 条也是空盒子 | 有 `thumb_path` 就贴海报；83 个资产全部有图 |
| 11 | **镜头墙"全项目"是 id 倒序** | 接口按 id 倒序给，页面直接铺；第 7 段排最左，和"本集"（正序）不是一个口径 | 按（集顺序, 片段号）排 |
| 12 | 文案与布局细节 | S5 结果还写"provider.image 未实现"（出图早就有了）；槽位弹窗把 `**项目级**` 原样显示成星号；加了项目下拉后"＋项目/退出"被挤成竖排 | 改文案；头部按钮 `flex:none; white-space:nowrap`，两个下拉 `max-width:240px` |
| 13 | **动线质检全部降级成 `unknown`**，界面写"vscan 执行失败：PermissionError" | 两层叠在一起：①`vscan.ps1` 带 Mark-of-the-Web，当前策略是 RemoteSigned，PowerShell 直接 `SecurityError` 拒载（`-NoProfile` 不绕过执行策略）；②`scan()` 只把异常类型写进 note，真正的第一行 stderr 被丢掉，于是看起来像"没权限"，实际是"没签名/被标记"。这个错误**不会让 job 失败**（设计上要降级），所以只有人看质检结论时才会发现整套片子都没被真判过 | `review.py`：宿主命令加 `-ExecutionPolicy Bypass`；失败时把 stderr 第一行带进 note。修后同一片段 `23 采样点 / avg 28 / max 49.63 / 冻结 0`，判据 a1 `pass（开场动线 35.04）`，trace 里 review 步骤 1794ms |
| 14 | 版本链把**刚产出的那一版**标成"回滚到此版" | `PayPoint` 收到的是打开弹窗那一刻的 clip 快照；出片后 `current_revision_id` 已经变了，快照没变，于是"当前"没人认领、当前版本还挂着"回滚到此版" | 渲染时用当前列表里的最新一份（`clips.data.find(...)`，全项目跨集时退回快照） |
| 15 | **点"对比上一版"回 500**："服务内部错误，请附带 request_id 反馈" | 契约对不上：`RevisionDiff.params_diff` 声明成 `dict[str, list[str \| None]]`，而 `params_json` 里实际有对象（S4 的 `prompt`）、整数（`skill_sections`）、布尔（`trimmed`）——pydantic 校验当场炸；原来的契约用例只用了字符串参数，所以一直没撞到 | `schemas.py` 改成 `dict[str, list[Any]]`（diff 就是任意 JSON 的 before/after），`test_api_contract` 的用例补上对象/整数/布尔三种值；顺手让 diff 成功时清掉上一条错误提示 |

### 修完的回归

`pnpm exec tsc -b --force` 通过（exit 0），`pnpm build` 重新出包，然后在**新构建**上重跑：
项目切换 / S1→S2 头部即时更新（`修仙 · 荒诞反差喜剧`、`（scripted）`）/ 412 行内红字 / 重发弹窗版本链 + 取消 /
镜头墙 13 个片段海报 / 资产库 83 个资产海报 / 成本按集 `¥50.78 + ¥7.19 = ¥57.97` / Skill 422 红字 / 1440 下无横向溢出 /

`对比上一版` 出 unified diff / `回滚到此版` 把 v1 设成当前且片段回到 `rejected`。

## 5. 只记录、没动的（要产品/后端拍板）

1. **归档不可逆**：`PATCH /projects/{id}` 把 `status` 改成 `archived` 之后，同一个 owner 再改回 `active` 会 `403 PERM_READONLY_PROJECT`。界面上没有归档入口，所以只会在脚本/API 侧踩到。
2. **错误详情被前端丢掉**：预算填 `0` 或 `abc`，后端都回 422，`detail` 里分别带着 `field/max` 和"只接受十进制数字符串（不接受科学计数法、NaN、全角数字）"，而弹窗只显示 `message`（"参数超出允许范围"）。要么后端把话说全，要么前端把 `detail` 拼上去 —— 两边只做一边就够了，同时做会重复。
3. **a11y**：登录邮箱/口令、预算、Skill 正文等 3–5 个控件没有 `id`/`name`（Chrome 直接给 issue）；模态有 `role=dialog aria-modal` 但没有焦点陷阱，Esc 也不关。
4. **`-ExecutionPolicy Bypass` 是安全姿态上的选择**：只作用于"用户用 `VSCAN_PATH` 明确指过来"的那个脚本子进程，不是全局改策略。如果团队不接受，替代方案是在 README 里让人先 `Unblock-File tools\vscan.ps1`（去掉 Mark-of-the-Web），代码则保持原样 —— 但那样新克隆的人第一次还是只会看到 `unknown`。

## 6. 仍然没覆盖到的

- **402 项目日预算**：要先把当天花到 100 元，mock 下也得真跑十来条；这轮没造这个前置状态。
- **真 provider 下的界面**：出图/出片的"真调用"标识、真实耗时、真视频海报都只验证了 mock 分支。
- **多标签页**：SSE 是进程内总线，两个标签同时看一个项目时的事件顺序没测。
- **窄屏**：1440×900 全过，1024×768 也能用（两列、S4 下拉照常可读）；**420 宽直接崩**——标题挤成竖排、头部横向溢出、tab 文字被折断。桌面工作台没做断点，这轮只把它测清楚、不修。
- **`fail` 分支是靠手工造判据补上的**：mock 文本生成的验收点只有"开场不是定镜"这一类，动线能直接判，所以出片基本直接 approved。手工给片段加一条 `画面不出现烧入字幕或水印`（mock 视觉对"字幕/水印"判 fail）后出片：质检 `PASS 开场动线 35.04 / FAIL [mock] 画面出现烧入文字`、job `failed + ESCALATED`、片段停在 `review`、`decision` 步骤记 `failure_type=acceptance_fail`。同一轮把 `通过`、`对比上一版`、`回滚到此版` 也点了（`对比上一版` 撞出缺陷 15）。
