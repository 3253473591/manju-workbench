# 03 · 异常包容与边界值

> 本文回答两个问题：**什么东西会坏、坏了怎么办**（异常包容），以及**输入的极限在哪、越界报什么**（边界值）。
> 错误码的权威定义在 `02` §4；本文只规定每一类异常由谁处理、重试几次、要不要计费、状态怎么迁移。

---

## 1. 分层模型

| 层 | 异常举例 | 谁负责吸收 | 能否自动恢复 |
|---|---|---|---|
| **L1 传输/协议** | 请求体不是 JSON、字段类型错、缺必填、超出长度 | `apps/api`（pydantic） | ❌ 只能告诉用户改 |
| **L2 业务规则** | 权限不足、版本过期、状态非法、序号冲突、预算不足 | `service` + `domain` | ❌ 需要用户或管理员决策 |
| **L3 外部依赖** | 429 / 5xx / 超时 / 鉴权失败 / 内容审核拒绝 | `providers` + `jobs` | ✅ 部分可重试 |
| **L4 Agent 语义** | 输出不是合法 JSON、分镜不闭合、验收点失败、归因不出 | `agent` + `domain` | ✅ 有限次自愈 |
| **L5 基础设施** | DB 连接断、磁盘满、worker 崩溃、SSE 断连 | `infra` | ✅ 靠重连/回收 |

**包容原则**（写进代码注释，review 时据此判断）：

1. **不可执行的必须拒**：结构不自洽（分镜不闭合、台词未内嵌、槽位序号断裂）会让模型自由发挥并烧钱 → 422，宁可让用户改。
2. **只是"可能不好看"的要放行**：台词偏快、参考图超推荐数量、单片段 15 s 顶格 → 只记评测指标，不拦。**质量判断不上升为校验错误。**
3. **绝不静默吞掉**：可降级就降级并告知；不可恢复就报错并给 `request_id`。没有第三种选择。
4. **不把上游原文当用户文案**：provider 报错进 `detail.raw` 与日志，`message` 必须是人话。
5. **只记真实发生的调用**：上游返回成功即计费，产物拉不回来也不许把费用丢掉（§3.1）；上游被调了两次就记两条（§8.3）。台账记录的是"调用发生了"，不是"我们打算让它发生"。

## 2. 异常归属矩阵

| 异常 | 层 | 处理 | 错误码 |
|---|---|---|---|
| JSON 解析失败 / 字段缺失 / 多余字段 | L1 | 直接拒（`extra="forbid"`） | `VALIDATION_SHAPE` 422 |
| 数值越界（时长、镜头数、分页） | L1 | 直接拒 | `VALIDATION_RANGE` 422 |
| 密码过短、邮箱格式 | L1 | 直接拒 | `VALIDATION_RANGE` 422 |
| 未登录 / 无权限 / 只读项目 | L2 | 直接拒 | `AUTH_*` / `PERM_*` |
| `If-Match` 不匹配 | L2 | 拒，前端自动 refresh | `STALE_VERSION` 412 |
| 同一集内 clip 序号冲突 | L2 | 拒 | `CONFLICT_CLIP_INDEX` 409 |
| 项目已有生成任务 | L2 | 拒，带 `Retry-After` | `PROJECT_BUSY` 429 |
| 预算不足 | L2 | 拒（**在提交前就拒**） | `BUDGET_EXCEEDED` 402 |
| 非法状态迁移 | L2 | 拒 | `JOB_STATE_INVALID` 409 |
| DB 唯一键/`CHECK` 违反 | L5→L2 | 映射成对应业务码；`CHECK` 违反一律 `INTERNAL_STATE` | 见 `01` §10 |
| provider 429 / 5xx / 超时 | L3 | 自动重试（§3） | 最终 `PROVIDER_*` |
| provider 鉴权失败 / 额度耗尽 | L3 | **不重试**，告警 admin | `PROVIDER_AUTH` 502 |
| 内容审核拒绝 | L3 | **不重试原样**，改提示词后再提 1 次 | `CONTENT_REJECTED` 422 |
| LLM 输出非 JSON | L4 | 修 JSON 重试 1 次 → 换强 prompt 1 次 | 最终 `VALIDATION_SHAPE` |
| 分镜不闭合 | L4 | **规则修补**，不消耗重试 | — |
| 验收点失败 | L4 | 归因 → 定向改写 → 重跑（≤3） | 最终 `ACCEPTANCE_FAIL` |
| 归因不出来 | L4 | **停止自动流程**，转人工 | `ESCALATED` |
| worker 崩溃 | L5 | 心跳超时 120 s → 重新入队 | — |
| SSE 断连 | L5 | 客户端重连 + `Last-Event-ID` 续传 | — |
| 幂等键命中（同 key 同 body） | L1 | **不执行**，返回原 job | 200 + `Idempotency-Replayed: true` |
| 幂等键非法 / 超长 / 生成类端点未带 | L1 | 在鉴权之后、`If-Match` **之前**判 | `VALIDATION_SHAPE` 422 |
| 上游成功但产物下载失败 | L3→L5 | 下载重试 2 次；仍失败则 job 失败，`revision` 照落 cost | `ASSET_FETCH_FAILED` 502 |
| 同一 job 被两个 worker 同时执行 | L5 | 校验 `locked_by` 令牌：非持有者不写 `state`/`attempts`/`clip`，产物与费用照实落 | —（内部告警） |
| 取消与完成竞态（cancel 后上游才返回） | L2 | `cancelled` 终态不变；产物照实落 `revision` 与费用，**不回写 `clip` 状态** | — |
| 写操作在目标行已消失后到达 | L2 | 按 `NOT_FOUND` 拒，不吞成 200 | `NOT_FOUND` 404 |
| 登录/注册失败过频 | L1 | 进程内计数，冷却期内直接拒 | `RATE_LIMITED` 429 + `Retry-After` |
| 配置缺失（provider Key / 单价 / 容量表） | L5 | **启动即失败**，不带病运行 | 进程非零退出 |

## 3. 外部依赖处理矩阵（实现级参数）

| 场景 | 检测 | 策略 | 上限 | 退避 | 计费 | job 终态 |
|---|---|---|---|---|---|---|
| HTTP 429 | 状态码 | 重试 | 3 | 1 s / 2 s / 4 s + ±20% jitter，优先用 `Retry-After` | 未产生请求则不计 | — |
| HTTP 5xx | 状态码 | 重试 | 3 | 同上 | 不计 | — |
| 连接超时 / 读超时 | 客户端 timeout | 重试 1 次 → 降级备用 model | 2 | 立即 | 不计 | — |
| 4xx（非 429/非审核） | 状态码 | **不重试** | 0 | — | 不计 | `failed` |
| 内容审核拒绝 | `error.code ∈ {content_policy, sensitive}` | 不重试原样；按 `skill` 的内容安全规则改写后**重提 1 次** | 1 | — | 首次可能已计费 | `failed` 或转人工 |
| provider Key 失效 / 额度耗尽 | `401/403` 或 `quota` | 不重试，标记 provider `unhealthy`，发 SSE `provider.updated` | 0 | — | 不计 | `failed` |
| 上游返回成功但无产物 | 结果校验 | 视为失败，重试 1 次 | 1 | 立即 | 通常已计费，**照实记账** | `failed` |
| 连接拒绝 / DNS 失败 / TLS 证书错误 | 异常类型（非超时） | 不重试同一 endpoint，计入熔断失败数（连续 5 次 → `unhealthy`，§7.2） | 0 | — | 不计 | `failed` |
| `Retry-After` > 300 s | 响应头 | **不排队干等**，直接失败并提示"上游限流，X 分钟后重试" | 0 | — | 不计 | `failed` |
| 上游 200 但 JSON 结构变更 / 必需字段缺失 | 结果 schema 校验 | 视为上游故障，**不重试**（同结构再试必错），告警 | 0 | — | 照实记账 | `failed`（`PROVIDER_UNAVAILABLE`） |
| 未知 `error.code` | 兜底 | 归**不可重试**（未知不等于瞬时，重试只会重复烧钱） | 0 | — | 不计 | `failed`（`PROVIDER_UNAVAILABLE`） |

**计费铁律**：只要上游返回了成功响应，就按 `revision` 落账，**哪怕产物不可用**。反过来，完全没拿到响应的重试不记费用。台账宁可偏高，不可漏记。

### 3.1 产物下载与落盘（上游成功之后的另一半链路）

上游给的是**限时签名 URL**，不是成品文件。这段必须单独规定，因为它失败时"钱已经花了、片子还没有"，既不能算 provider 失败，也不能算 `INTERNAL`。

1. **超时与内存**：单产物 `MEDIA_DOWNLOAD_TIMEOUT`（120 s），**分块写盘、不整段读进内存**；边下边累加字节数，超过 `asset.bytes` 上限（50 MB）立即中止并删临时文件。
2. **入库顺序不得颠倒**（`revision` 只增不改，`01` §4.6 的 update 护栏会拒绝任何回填）：
   ```
   上游 200 → INSERT asset(kind='video', source='gen', revision_id=NULL)
            → INSERT revision(output_asset_id=asset.id, cost=实测费用)
            → UPDATE asset.revision_id = revision.id
            → UPDATE clip.current_revision_id / status
   ```
   即 `asset` 先落地、`revision` 随后引用；**绝不为回填 `revision.output_asset_id` 去 UPDATE `revision`**。
3. **下载重试**：`ASSET_DOWNLOAD_RETRY = 2`，退避 1 s / 4 s。**签名过期（403/410）不重试** —— 同一个签名 URL 再试一次必然还是 403。
4. **彻底失败**：`revision` **照落**（`cost` = 实际费用、`output_asset_id = NULL`），job → `failed` + `ASSET_FETCH_FAILED`，上游 URL 存进 `job.error_detail.output_url`。**费用绝不能因为这个失败而丢失。**
   `error_detail` 里的 `output_url` 是**能力型字段**（带签名的直链，谁拿到谁能下载），只进服务端日志与恢复流程，**API 响应里必须剔除**；`raw` 可以返回（它是排查文本，前端折叠显示）。
5. **事后补拉**：这类 job 的 `retry` 只重下载，不再调上游（`error_detail.resume = "asset_fetch"` 标记）。成功后**新增**一条 `cost = 0` 的 `revision`（`parent_revision_id` 指向第 4 步那条），再把 `clip.current_revision_id` 指过去。**URL 已过签名有效期则无法补拉**，此时如实告知"需重新生成"并由用户决定 —— 别用"再花一次钱重生成"糊过去，也别拿坏链接硬试。
6. **磁盘满 / 只读文件系统**：映射 `INTERNAL`，但**先把 `revision.cost` 落库**。临时文件落 `MEDIA_ROOT/.tmp`，进程启动时清理 24 h 以上残留。

## 4. Agent 语义异常（最容易失控的一类）

### 4.1 停止判据（缺一即视为 bug）

一次自动流程（尤其全能模式）**必须同时**具备：

```
1. attempts ≤ 3
2. cost_used ≤ budget_limit          （检查在每次调用之前）
3. 下列任一成立即停：
   - 全部验收点 pass
   - 归因失败（无法说出"下次改什么"）
   - 同一 failure_type 连续出现 2 次且 fix 相同 → 说明改动无效，转人工
4. attempts 用尽 → 转人工，不自动延长
```

第 3 条的"连续两次同因同修即停"是防死循环的关键：没有它，Agent 会重复同一句改写三次，烧完预算还什么都没变。

### 4.2 归因质量门槛

`lesson` 只有在满足下列条件时才允许用于自动改写：

| 条件 | 不满足时的行为 |
|---|---|
| `failure_type` 能落到枚举内 | 转人工 |
| `fix` 指向**具体可编辑字段**（`prompt` / `negative` / `ref_slots` / `shots`） | 转人工 |
| `fix` 与上次同因的 `fix` 不同 | 判定改动无效，转人工 |
| `evidence` 指向具体时间码或验收点 id | 转人工 |

**归因不出来就不重试**，这一条比"多试几次"值钱。

### 4.3 上下文超预算（不报错，只裁剪）

- 组装结果 > 12,000 input tokens → **按 `01`/PRD §6.1 的顺序裁剪**，并在 trace 里记 `trimmed: true` 与被裁项。
- 裁剪后仍超 → 报 `INTERNAL_STATE`（说明预算表本身算错了，是 bug 不是用户问题）。
- 用户可见提示：`"已自动压缩上下文（裁掉人物详述）"`，放在 job trace，不弹窗。

### 4.4 Skill 越权

| 情况 | 处理 |
|---|---|
| `body_md` 含脚本围栏（```` ```bash ```` / ```` ```python ```` 等） | `422 SKILL_TOOL_UNKNOWN`，拒绝保存 |
| `tool_ref` 不在 allowlist | `422 SKILL_TOOL_UNKNOWN` |
| 单节 >2000 字 / 总 body >200,000 字符 | `VALIDATION_RANGE` 422 |
| 未通过 dry-run 就 publish | `SKILL_NOT_DRYRUN` 409 |

## 6. 边界值总表

### 6.1 字符串（长度按 **Unicode 码点** 计，非字节）

| 字段 | 最小 | 最大 | 越界 |
|---|---|---|---|
| `email` | 5 | 190 | `VALIDATION_RANGE` |
| `password` | 10 | 72 | 同上（且禁纯数字） |
| `project.title` | 1 | 200 | 同上 |
| `project.logline` | 0 | 500 | 同上 |
| `episode.title` | 0 | 200 | 同上 |
| `episode.synopsis` | 0 | 200,000 字符 | 同上（真实 4.6–20.9 KB） |
| `clip.prompt` | 0 | 20,000 字符 | 同上（真实单片段 2–4 KB） |
| `clip.title` | 1 | 200 | 同上（可选字段；给了就不能是空白串） |
| `clip.negative` | 0 | 2,000 字符 | 同上 |
| `shots[].desc` | 1 | 2,000 字符 | 同上 |
| `dialogue[].text` | 1 | 200 字符 | 同上 |
| `acceptance[].criterion` | 1 | 200 字符 | 同上 |
| `lesson.symptom` | 1 | 500 字符 | 同上 |
| `lesson.fix` | 1 | 2,000 字符 | 同上 |
| `skill_version.body_md` | 1 | 200,000 字符 | 同上 |

**空值语义**（PATCH 三态，必须严格区分）：

| 传法 | 含义 |
|---|---|
| 字段**省略** | 不修改 |
| 字段为 `null` | 清空（置 NULL） |
| 字段为 `""` | **非法**，`VALIDATION_SHAPE`（除 `tone`/`logline` 明确允许空串） |

> `""` 的合法性以 §6.1 各字段的**最小长度**为准：最小长度 1 的（`project.title`、`shots[].desc`、
> `dialogue[].text`、`acceptance[].criterion`、`lesson.*`）空串一律拒；最小长度 0 的
> （`episode.title`/`synopsis`、`clip.prompt`/`negative`、`tone`/`logline`）允许空串与空白串，
> 因为"还没写"必须能表达。这两条若要统一，先改 §6.1 的 min，别只改这一行。

**空白与不可见字符**（只规定 `""` 是不够的，下面三条都要写进校验器）：

1. **先 `strip()` 再判长度与空**：`"   "` 与 `""` 同义。`project.title = "   "` → `VALIDATION_SHAPE`，而不是存进一行的空白标题。
2. **控制字符**：`\x00`–`\x1f` 一律拒（`prompt` / `body_md` / `synopsis` 里的 `\n`、`\t` 例外，因为它们是正文结构）。**零宽字符**（U+200B–U+200D）与**双向控制符**（U+202A–U+202E、U+2066–U+2069）在 `title` / `email` 这类标识性字段上拒 —— 它们能让两个不同的标题在 UI 上长得一模一样。
3. **码点口径的副作用要接受**：`👨‍👩‍👧` 是 5 个码点，`title` 的 200 上限对它按 5 计。DB（`utf8mb4_0900_ai_ci`）与 Python 都是码点，前后端提示"约 N 字"时按码点算，不另做估算。

### 6.2 数值

| 字段 | 范围 | 边界行为 |
|---|---|---|
| `clip.duration_s` | **1.00–15.00** | `15.00` 允许，`15.01` 拒（Seedance 单片段硬上限） |
| `shots[].no` | 1–8，连续 | 空数组拒；9 个拒 |
| `shots[].start/end` | `0 ≤ start < end ≤ duration`；末镜 `end == duration ±0.05` | 不闭合 → `VALIDATION_INVARIANT` |
| `ref_slots` | 0–上限，**按模型系列查表**（§6.2.1） | 超容量 → `422 MODEL_REF_LIMIT`；三类槽位分开计数 |
| `ref_slots[].idx` | 从 1 连续 | 断号 → `VALIDATION_INVARIANT` |
| `episode.idx` | 1–50 | 超 50 `VALIDATION_RANGE` |
| `clip.idx` | 1–30 | 同上 |
| `asset.w/h` | 0–8192 | 超限拒 |
| `asset.bytes` | 0–52,428,800（50 MB） | 超限 `PAYLOAD_TOO_LARGE` |
| `job.attempts` | 0–3 | DB `CHECK` |
| `budget_limit` | 0.01–100.00 | 超上限 `VALIDATION_RANGE`；不足 `BUDGET_EXCEEDED` |
| `page limit` | 1–200 | 超 200 截到 200 而非报错（分页是"用户体验"不是"业务正确性"） |
| `cursor` | 正整数 | 非法或已删 → 返回空 `items` + `next_cursor: null`，**不报错** |

#### 6.2.1 参考槽位容量（**模型能力，不是全局常量**）

| 模型系列 | 图片 | 视频 | 音频 |
|---|---|---|---|
| `seedance-2.0`（mini / 720p / fast） | **9** | **3** | **3** |
| `seedance-2.5` | **30** | **10** | **10** |
| `gemini-3.1-flash-image-preview` | **10** | — | — |
| `gpt-image-2.5`（flare / sunburst） | **10** | — | — |

三条硬规矩：

1. 容量来自 provider 配置，校验时按**当前将要调用的模型**读，不写死在 domain。真实第一集最多用到 6 张图，但 seedance-2.0 允许 9 张 —— 按实测值当上限会把能力关掉。
2. **降级换模型必须重新校验**：30 图请求从 2.5 降级到 2.0 会直接非法。此时报 `MODEL_REF_LIMIT`，**不允许降级后静默砍图** —— 砍图等于悄悄改创作意图。
3. `0` 个参考图合法（纯文生视频）；图片/视频/音频三类槽位分开计数，互不占额度。

**浮点与精度**：秒/金额全程 `Decimal`，Python 侧禁止 `float` 参与比较；比较时长用容差 `0.05 s`。

**字符串形态的数值**（`budget_limit`、`duration_s` 入参，`cost`、`seconds` 出参）：客户端传的是 string，`Decimal()` 之前必须先判形态，否则"金额被静默改值"是最好复现也最难发现的一类 bug。

| 输入 | 处理 |
|---|---|
| `" 12.00 "` | 允许，`strip()` 后解析 |
| `"12"` / `"12.0"` | 允许，归一化补零后比较与落库 |
| `"1.2e1"` / `"NaN"` / `"Infinity"` / `"-0"` | **拒**，`VALIDATION_RANGE`（科学计数法与特殊值不接受） |
| 全角数字 `"１２"` | **拒**，`VALIDATION_RANGE` |
| 金额 7 位以上小数 `"12.0000001"` / 时长 3 位以上小数 | **拒**，不四舍五入 —— 超存储精度时让调用方显式给值，静默截断会让用户看到的钱与台账对不上 |

反过来，**provider 回传**的毫秒精度时长按 `00` §3.3 截到 0.01 s（`12.043 → 12.04`）—— 那是入站归一化，不是校验，别和上表混用。

**零值**：`cost = 0` 合法（dry-run、失败未计费、事后补拉产物、Skill 版本）；`duration_s = 0`、`budget_limit = 0` 非法。

### 6.3 数组与集合

| 集合 | 空集合 | 说明 |
|---|---|---|
| `ref_slots` | 允许 | `[]` 与 `null` 等价于"无参考图" |
| `shots` | **不允许** | 至少 1 个镜头，否则无法生成。只在 `draft` 阶段可空；迁到 `prompted`（分镜完成）时强制非空（`01` §5.4） |
| `dialogue` | 允许 | 纯画面片段（真实第一集有此类镜头） |
| `acceptance` | 警告不拦 | 无验收点则质检只能给 `motion` 级提示，评测记 `acceptance_pass_rate = null` |
| `project_member` | 允许 | owner 不在表里（见 `01` §5.2） |

### 6.4 时间与时区

- 所有时间入参出参均 UTC；`from`/`to` 必须是 UTC 日期（`YYYY-MM-DD`），成本按 **UTC 日切**聚合 —— 与使用者本地跨日不一致，前端必须标注"按 UTC 计"。
- `from > to` → `VALIDATION_RANGE`；`from == to`（单日）合法。
- 时间跨度上限 366 天（防全表扫描）。
- **唯一时钟是 DB 的 `NOW(3)`**：锁过期、心跳僵死、日切聚合、presence 在线判定，全部用 SQL 里取的时间；**不用应用进程时间**做这些判断（进程 NTP 回拨 1 秒就会让锁"忽有忽无"、让僵死判定误杀正在跑的 worker）。进程时间只用于打日志。
- 边界一律**左闭右开**：`lock_row.expires_at <= NOW(3)` 即过期（可用窗口是 `[获取时刻, expires_at)`）；`presence.last_seen_at > NOW(3) - 30 s` 算在线；`cursor` 恰好等于最新 id → 空页 + `next_cursor: null`。这几处只要一个用 `>`、一个用 `>=`，"锁永远差 1 秒"和"最后一页少一条"就会同时出现。
- job 的墙钟上限是 `JOB_TOTAL_TIMEOUT`（1 h），与单次调用的 `TIMEOUT_*` 是两层：单次超时→重试，总超时→停。别只设单次超时，3 次 1800 s 叠加能把一个 job 挂到 1.5 小时。

### 6.5 并发

| 场景 | 上限 | 超出行为 |
|---|---|---|
| 同项目同时进行的 `video` job | **1** | `429 PROJECT_BUSY` + `Retry-After: 5` |
| 同项目同时进行的 `text`/`image` job | 3 | 排队，不拒 |
| 同用户同时 SSE 连接 | 5 | 第 6 条返回 `429` |
| 同 clip 的编辑锁 | 1 | `409 LOCK_HELD`（仅提示，不阻止写入） |
| 同 `Idempotency-Key` 并发请求 | 1 次真实执行 | 后到者等前者完成后重放结果；DB 唯一索引兜底 |
| 非 PATCH 写操作（`rollback` / `archive` / `confirm` / `cancel` / `retry`） | 1 次有效执行 | 不带 `If-Match`，**靠状态机幂等**：重复提交返回 `JOB_STATE_INVALID` / `CONFLICT_*`，不引入新锁 |

不带 `If-Match` 的写端点等于放弃了乐观锁，所以它**必须**由状态机或唯一键兜住。以后新增任何不带 `If-Match` 的写端点，都要在本表登记一行并写清"重复提交返回什么"，否则并发两次就是两份副作用。

### 6.6 未启用项（本版不做，边界先留位）

用户上传资产（PRD §2.4 已砍）：`POST /assets/upload` 不存在。上表 `asset.bytes` 的 50 MB 上限仅用于 **seed 导入校验**，别提前实现上传路径。

**seed 导入是唯一读本地文件的入口，也是唯一的路径遍历面**：`scripts/seed_project.py` 的根目录来自常量，**不接受 API 传入路径**；解析出的 `asset.path` 必须是 `MEDIA_ROOT` 的**相对路径**且 `realpath` 后仍在 `MEDIA_ROOT` 之内（`01` §4.5 的"禁止绝对路径"是这条的落库侧确认）。软链/`..` 越界一律 `INTERNAL` 并中止导入。

其余未启用项的对外语义见 §12.2。

### 6.7 协议层边界（不是字段边界）

字段边界在 §6.1/§6.2 管，这一节管"请求还没进业务就坏了"的那一层。

| 场景 | 处理 |
|---|---|
| 路径参数非法（`/clips/abc`、`/clips/-1`、超出 `BIGINT UNSIGNED` 的 20 位数字、`/clips/1.5`） | `422 VALIDATION_SHAPE` —— **不是 500，也不是 404**。格式非法与"格式合法但不存在"必须分开，否则前端无法判断该改 URL 还是该提示资源已删 |
| 路径参数合法但无此记录（`/clips/999999`） | `404 NOT_FOUND` |
| 查询参数非法（`limit=abc`、`group_by=foo`、`from=2026-13-40`、`mode=bogus`） | `422 VALIDATION_RANGE` / `VALIDATION_SHAPE`；`group_by` 这类枚举走 `VALIDATION_RANGE` |
| 同一 query 参数重复（`?limit=10&limit=200`） | 取**最后**一个（Starlette `QueryParams.get` 的默认行为，实测 Starlette 1.6 / FastAPI 0.141）。契约里写死这条，别让两个实现各取一个 |
| `Content-Type` 不是 `application/json`（含 `charset` 之外的写法） | `415 UNSUPPORTED_MEDIA` |
| 请求体 > `BODY_MAX_BYTES` | `413 PAYLOAD_TOO_LARGE`，**在反代/ASGI 层就拒**，不读进内存；`body_md` 的 200,000 字符上限是业务边界，这里是传输边界，两者都要 |
| 请求体不是合法 UTF-8 / 不是合法 JSON | `422 VALIDATION_SHAPE`，`detail` 只给位置（`line/col`），不回显原文 |
| 数字 id 的 JSON 形态（`{"project_id": "2"}` 传成字符串） | pydantic v2 严格模式拒 → `VALIDATION_SHAPE`；不要为兼容前端而开 `coerce` |
| 客户端版本落后（缺少新必填字段） | 见 §12.3 兼容规则，不加兼容分支 |

## 7. 降级与熔断

### 7.1 provider 降级链

```
video.draft:  seedance-2.0-mini  → （失败）→ 不降级，直接失败      # 便宜那档没有更便宜的替代
video.final:  seedance-2.0-720p  → seedance-2.0-mini              # 正片失败降草稿，比什么都不出强
              （若把 seedance-2.5 配成 primary，降级回 2.0 时容量从 30/10/10 掉到 9/3/3，必须重校验）
text.plan:    primary-llm    → secondary-llm                      # 两家不同厂商
img.draft:    gpt-image-2.5-flare → gemini-3.1-flash-image
img.edit:     gpt-image-2.5-sunburst → 不降级（精修没有等价替代）
```

降级发生时：`job.provider` 记实际使用者，`revision.model_used != model_requested`，UI 在结果卡上标"已降级"。

### 7.2 熔断

- 单 provider 连续失败 5 次 → `unhealthy`，冷却 300 s，期间所有请求走降级链。
- 冷却期结束探测 1 次成功即恢复。
- 状态存在进程内（`2–5` 用户单实例，无需 Redis）+ 落 `admin/providers` 可见。
- **kill switch**：admin `PATCH /admin/providers/{name} {enabled:false}` 立即停用，所有相关 job 快速失败 `PROVIDER_UNAVAILABLE`。

### 7.3 全局预算制动

- 项目日成本达 `BUDGET_PROJECT_DAILY` → 新的生成请求直接 `402`，不做"再试一次"。
- 判断在**提交前**（`service`），不在循环里；循环内的预算检查是第二道，只针对单 job。

### 7.4 质检降级链

质检有三档，**判不了就返回 `unknown`，不猜**（`02` §11.1）：

| 环节 | 依赖 | 缺失时的行为 |
|---|---|---|
| 动线采样 | `vscan.ps1` + PowerShell 宿主 | `degraded=true`，动线类判据 `unknown` |
| 内容级判定（抽帧） | `ffmpeg` + `ffprobe` | `note` 写明缺什么，判据保持 `unknown`，链路继续跑 |
| 内容级判定（视觉模型） | provider 的 `vision()` | 现只有 `mock`（预设表，evidence 带 `[mock]`）；真 provider 未接时同样保持 `unknown` |

三条约束：

- **降级不等于通过**：任一档缺失都只会让判据停在 `unknown`，`clip.status` 不会自动 `approved`。
- **`VISION=0` 可整体关掉视觉判定**，回到"只跑动线"的口径 —— 用于对比演示与省钱。
- 抽帧与判定都在 `running` 的同一个事务里，失败只回滚后处理，**provider 已产生的费用照记**（§3 计费铁律）。

## 8. 幂等与重复提交

### 8.1 幂等键的构造与作用域

- 服务端存的不是头值本身，而是 `idem_key = sha256(f"{user_id}:{Idempotency-Key}")`，落 `CHAR(64)`（`00` §3.4）。
- **`user_id` 参与 hash** → `uk_job_idem` 保持全局唯一就够用，两个用户用同一个字符串互不干扰，`01` 的表结构不用改。
- 头值长度 1–`IDEM_KEY_MAX`（128），字符集 `[A-Za-z0-9._:-]`；超长或含非法字符 → `422 VALIDATION_SHAPE`。
- 保留期：**永不过期**（`job` 行不删，`01` §9 单项目量级 < 6000 行）。所以客户端**每次新的逻辑提交都必须新生成 key**（`02` §8 的 `crypto.randomUUID()`）；禁止用 `"retry-1"` 这类语义化固定串 —— 那等于把第二次提交毒化成重放。
- **校验时机在 `If-Match` 之前**（`02` §5.3）。命中即重放，跳过 `If-Match`、预算、domain 校验：它不产生任何新执行，任何"重放却 412/402"的行为都是 bug —— 而客户端超时重试恰恰是幂等键唯一的真实使用场景，先验版本就等于让它永远失效。

### 8.2 各写端点的重复提交行为

| 端点 | 重复提交 |
|---|---|
| `POST /clips/{cid}/generate`、`/reroll`、5 个 `steps/*/run` | 同 key → 重放原 job；同 key 异 body → `409 IDEM_KEY_REUSED`；同 key 并发 → 后到者查 `uk_job_idem` 冲突后读行，首个未落库最多等 3 s，超时 `429` |
| `POST /jobs/{jid}/retry` | **不带幂等键**：它是 job 状态迁移（`attempts+1`），复用原行与原 `idem_key`；重复调用由状态机兜底。`attempts` 已达 `max_attempts` → `409 JOB_STATE_INVALID`，**提前判，别让 DB 的 `ck_job_attempt` 去炸成 `INTERNAL_STATE`** |
| `POST /jobs/{jid}/confirm` | 已 `queued` → `409 JOB_STATE_INVALID` |
| `POST /jobs/{jid}/cancel` | 已终态 → `409 JOB_NOT_CANCELLABLE` |
| `POST /clips/{cid}/rollback` | 目标版本已是 `current_revision_id` → 200，**不写新 revision** |
| `POST /skills/{sid}/versions/{v}/publish` | 该版本已 `active` → 200，不重复 supersede |
| `POST /projects/{pid}/archive` | 已归档 → 200，幂等 |
| PATCH 类 | 靠 `If-Match`，重复提交同样 412 |
| 未带 key 的生成请求 | `422 VALIDATION_SHAPE`（`Idempotency-Key` 对生成类端点是必填） |

> `retry` 曾经标了 `I`（需幂等键），这是错的：`job.idem_key` 是 `NOT NULL` + 全局唯一，一个 job 行没有第二个位置存新键；`retry` 本身就是对同一行的状态迁移，重复调用的正确答案是 `JOB_STATE_INVALID`，不是"又开一个 job"。

### 8.3 重复执行（同一个 job 被跑两遍）

§3 的心跳回收带一个反向风险：`TIMEOUT_VIDEO` 1800 s ≫ 心跳 120 s。worker 等上游时若心跳协程被卡住（长同步调用、GC、进程被挂起），job 会被判僵死并重新入队，**旧 worker 与新 worker 同时跑同一个 job**。规则（`01` §4.7 的 `locked_by` 就是为此存在）：

1. claim 时写 `locked_by = "{worker_id}#{uuid4[:8]}"`，这个值就是**执行令牌**。
2. **状态写入与 `attempts` 自增**的每条 SQL 都带 `AND locked_by = :token`；影响行数 0 → 说明 job 已被回收，立刻停手，不再走后续步骤。
3. **费用与产物照实落，不受令牌约束**：非持有者若已拿到上游响应，仍写它自己的 `revision` + `asset`，但**不写** `clip.current_revision_id` / `clip.status`。理由：上游确实被调了两次、确实收了两份钱，台账必须记两条；令牌要防的是"状态被两个 worker 竞争写"，不是"费用记两条"。
4. 因此这类 job 的 `trace` 里会出现两条 `provider_call`，`revision` 列表多一版 —— 都属正常，UI 不做特殊处理。
5. 收尾时 `locked_by = NULL` 必须带令牌条件，否则下一次 claim 会拿到残留令牌而误判持有。
6. 与 §6.5 的 `lock_row`（编辑锁）区分：那是**协作提示**，`locked_by` 是**执行所有权**，同名不同物，不要复用一个 helper。

## 11. 观测字段（每次失败必须能回答"哪一步坏了"）

每个 `job` 终态必带：`error_code`、`error_detail`、`attempts`、`cost_used`、`state`、`finished_at`。
每条 `trace` 必带：`ts`、`step`、`ms`；外部调用另带 `provider`、`model`、`tokens`、`cost`；质检另带 `verdict`、`failed[]`。

**验收口径**：给任意一个失败的 job id，能在 30 秒内定位到"是组装错了、上游错了、还是验收没过"。

**admin 操作必须留痕**（`01` 不建审计表，落到结构化日志，`event=admin_action`）：
`user_id`、`action`（`provider.update` / `provider.kill_switch` / `skill.publish` / `skill.rollback`）、`target`、**变更前后值**、`request_id`、`ts`。
理由：kill switch 和 skill publish 都能在不改一行业务代码的情况下改变所有人的产出（和账单），出事后第一个要回答的就是"谁在几点关的/换的"。日志比一张表便宜，且不需要动 DDL 与迁移纪律。

## 12. 配置、环境与未启用项

### 12.1 启动即校验（宁可起不来，不要带病跑）

启动段（`lifespan`）逐项校验，任一失败就打印缺失项并非零退出。注意 **uvicorn 下退出码是 3 而不是 1**：
`lifespan` 里 `raise SystemExit(1)` 会被 uvicorn 记为"Application startup failed"并映射成 3（实测）。
探活脚本只判 `!= 0` 即可，别硬编码 1。

| 必须存在 | 缺失后果（为什么不能等到运行时） |
|---|---|
| provider 的 `api_key` / `base_url` | 请求时才 401，用户以为是自己参数错了 |
| provider 的**单价**（`PRICE_VIDEO_MINI` 等） | 成本恒为 0，**静默错账** —— 这是最伤台账的一条 |
| 参考槽位容量表（§6.2.1） | 校验退化成"无上限"，超容量请求跑到上游才失败，钱已经花了 |
| `MEDIA_ROOT` 且可写 | 产物无处落盘，§3.1 整条链路从第一步就断 |
| DB 连通与迁移版本 | — |
| CSRF 的 `Origin` 白名单非空 | 生产环境全员写请求 403，且报错原因看不出来 |

`constants.py` 与本文 §5 的数值必须一致，进 CI 校验（`00` §5 第 4 条：常量只有一个来源）；单测里不允许出现文档里没有的魔法数字。

### 12.2 本版明确不做（被请求时回答什么）

| 不做的东西 | 被请求时 |
|---|---|
| 资产上传 `POST /assets/upload` | `404 NOT_FOUND`（路由不存在，别留占位端点） |
| 批量生成（一次多 clip） | 路由不存在；请求体多传 `clip_ids` 由 `extra="forbid"` → `422 VALIDATION_SHAPE` |
| 缓存层 / Redis | 无缓存读路径；进程内状态仅限 12.4 白名单 |
| 消息队列 | 任务表即队列（`SKIP LOCKED`）；"重复投递"等价于 §8.3 |
| webhook / 上游回调 | 不接收，一律同步等待 + 超时 |
| 多租户 `tenant_id` | 单团队部署，权限到项目级（`02` §2.1） |
| `?mode=auto`（P1 全能模式） | 未启用时传值 → `422 VALIDATION_RANGE`，**不要静默忽略** —— 忽略等于承诺了一个不存在的行为 |

**"没做"必须显式**：不存在的端点返回 404 是一句话的事；存在但什么都不做的端点会让前端、测试、评审三方都误解范围。

### 12.3 环境差异与兼容

| 项 | 本地 / 测试 | 生产 |
|---|---|---|
| Cookie | 不带 `Secure` | `Secure; HttpOnly; SameSite=Lax` |
| CSRF `Origin` 白名单 | `http://localhost:5173` 等 | 配置注入，启动校验非空 |
| provider | `mock` 实现（§13 的注入用例依赖它）：固定 JSON + 可编程的 429/5xx/timeout/空产物 | 真实 provider |
| `revision` update 护栏（`01` §4.6） | 关闭（造数与 fixture 回放需要） | 开启 —— 线上任何 UPDATE `revision` 都是 bug |
| 日志 | 人读 | 带 `request_id` 的结构化行，可 grep |

兼容：单前端同仓部署（`00` §2），加字段前端忽略未知字段（`02` §9）；删字段/改语义不做双写期，直接 `/v2`。**不写旧客户端兼容分支** —— v0 没有第二个客户端，写了也没人用。

### 12.4 进程内状态白名单

允许存在、允许重启丢失、且**不得用于业务判定**的进程内状态只有四条：

| 状态 | 丢失后果 | 上界 |
|---|---|---|
| provider 熔断计数（§7.2） | 冷启动，可能多打几次上游 | 每 provider 一个计数器 |
| SSE 环形缓冲（`SSE_BUFFER`） | 客户端收 `resync` 全量刷新 | 按项目 100 条 × 事件 ≤8 KB ≈ 0.8 MB；同时在线 SSE 连接上限 5（§6.5）→ 内存上界 < 5 MB |
| 登录失败计数（`LOGIN_FAIL_LIMIT`） | 计数清零，冷却失效 | 每 `(IP, email)` 一条短 TTL 记录 |
| presence 的进程内索引（可选） | 以 `presence` 表为准重建 | ≤ 在线用户数 |

除这四条外，任何"为了快"加的进程内缓存都要先改这一节。尤其禁止把 `clip`/`job` 状态、预算余额、`version` 号放进内存 —— 它们一旦有第二份真相，就一定会不一致。
