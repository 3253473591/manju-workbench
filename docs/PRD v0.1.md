## 1. 先把约束钉死

| 维度 | 事实 | 对设计的强制影响 |
|---|---|---|
| 目标读者 | 20–99 人中小厂的 AI 应用开发岗面试官（AI 应用为主、全栈为辅） | 会被问的是**链路、取舍、异常、成本、评测**，不会被问"你有几个功能" |
| 项目性质 | 开源 Demo，非企业级 | 没有 SLA、没有多租户计费、没有合规审计 —— 这些做了也没人验证，只是负债 |
| 团队 | 2–5 人（学生/业余时间） | 单人有效时间按每周 5 人日算，且必须留 30% 给"踩坑 + 写文档" |
| 成功标准 | **3 分钟内能演示一条"想法 → 成片"的链路；被追问 8 个问题时都有具体数字或具体失败案例可讲** | 宁可 1 条链路跑 20 遍，不要 6 条链路各跑 1 遍 |
| 反面失败 | 功能表很长，但每条链路都在"demo 能跑、追问就露"的临界点上 | 这是面试里最掉分的形态：证明不了深度，还暴露了规划能力 |

### 判定"过度设计"的四条标准（后文全部按这个尺度）

1. **解释成本 > 实现成本**：实现了也讲不清，或讲清了但面试官不关心。
2. **一个用例却按通用能力建模**：演示路径上只会用到 1 种用法，却抽象成插件/DSL/DAG。
3. **把"能不能演示"变成"能不能不出 bug"**：并发、分布式一致性问题会把演示风险从"可能不好看"升级成"可能挂掉"。
4. **超出团队预算**：下面 §2.2 有账。

## 2. 对 PRD v0 的评估

### 2.1 v0 里做对了的 5 件事（保留，别动）

1. **草稿用便宜模型、正片换贵的**（mini 480P → 720P+）：这是真正的成本工程意识，面试里可以直接算钱。
2. **只做多参考图生视频**：主动接受上游能力的边界，不做图生视频/首尾帧/运镜控制的"全都要"。
3. **把 `video-motion-review` 作为 Agent 的审阅工具**：多模态质检闭环，是这条链路里最有说服力、也最便宜的一环。
4. **生成前先在付费点停下、逐 clip 确认**（默认模式）：这是产品感和成本控制的双重正确。
5. **鲁棒性被单独列成一条**：说明你知道 Agent 不是"调通 API 就完事"。

### 2.2 过度设计清单

工作量按"熟练 + 会用 AI 辅助"的人日估，不含调试。

| # | v0 条目 | 为什么对求职 Demo 过度 | 处置 | 替代方案 | v0 人日 → 裁剪后 |
|---|---|---|---|---|---|
| 1 | **Yjs 实时多人协作（画布 + 节点内容 + 光标 + undo）** | 领域内最难的一块（tldraw/FigJam 有专人做）。CRDT 状态 ↔ 画布图 ↔ 版本历史的**三方双向同步**是分布式一致性问题，标准 3 里全中。面试官大概率问不出深度，但你会为它烧掉一半工期，且演示时一旦抖动就是"当场挂" | **砍到最小**（见 Q2） | presence（谁在线/谁在看哪个节点）+ 节点级乐观锁（编辑中加锁、10s 过期）+ 变更广播。**把"为什么没上 Yjs"写成 README 的一节** —— 这个回答比半成品 CRDT 值钱 | 15–25 → 3 |
| 2 | **5 类文本节点**（总大纲/分集大纲/分集剧情/分集分镜/人物设定）各自成节点 | 典型的概念过度建模：它们是**同一个 LLM 步骤 + 不同提示词模板 + 不同输出 schema**，不是 5 种节点类型。做成 5 类节点，每加一环就改一次画布/序列化/前端/联调 | **合并** | 1 个 `LLMStep`，`template_id` + `output_schema` 从配置读。5 个环节 = 5 行配置 | 8–10 → 3 |
| 3 | **无限画布 + 自由 DAG 编排** | 漫剧生产链路本质是**线性**的（大纲→剧情→分镜→图→视频），DAG 的自由度没有用户，只有你。而且无限画布是纯前端重活：布局、连线、缩放、序列化、脏状态 | **降级**（见 Q3） | 主视图 = 线性流水线（阶段条 + 卡片列表），画布只作为**镜头墙/资产看板**的展示层。既保住了视觉冲击，又不承担编辑器复杂度 | 8–12 → 4 |
| 4 | **资产管理 + 节点内容版本 diff** | 价值高但**范围错了**：真正要 diff 的是**提示词与参数**（"这条 clip 为什么比上一条好"），不是图片/视频二进制。给二进制做版本管理是对象存储的活 | **缩小到提示词版本** | 每次生成 append 一条 `revision`（提示词 + 参数 + 模型 + 产出 + 成本 + 耗时），提供两版文本 diff + 一键回滚到某版提示词。**这同时是成本审计和复盘入口** | 8–12 → 3 |
| 5 | **"完整的登录系统" + 三角色**（邀请入组、账单筛选、超管后台、注册默认角色） | 三角色权限矩阵本身很便宜（一个中间件）；贵的是"完整"：邀请、找回密码、超管查询后台。这些是 SaaS 的活，不是 Demo 的活，且第 4 条标准全中 | **保留角色，砍掉"完整"** | 邮箱密码 + JWT + `require_role` 守卫 + 6 条权限的矩阵表。账单不做"管理"，只做**成本看板**（按项目 × 模型聚合 token/秒数/金额） | 6–10 → 2 |
| 6 | **"多模型 provider，根据网关决定发给哪个 API"** | 若指自建 LLM 网关（限速、配额、按量切流、健康检查）：这是基础设施项目，不是作品集项目。而且"网关决定"这个描述本身没定义决策输入（成本？延迟？能力？） | **降级为适配层 + 路由表** | 1 个 `Provider` 协议 + 按**任务类型**的路由表（`text.plan`/`img.draft`/`img.edit`/`video.draft`/`video.final`）+ 失败降级链。决策依据写死成配置，但**要有依据**（单价、`经验教训.md` #98 的火山涨价） | 5–8 → 3 |
| 7 | **Agent "全能模式"：自主发送、审阅视频、改提示词、重发** | 功能本身对（有演示价值），v0 的**缺省**过度：没写收敛条件、没写预算上限、没写"什么时候认输"。一个没有停止判据的自主循环 = 烧钱 + 不可复现 + 演示时可能卡死 | **加硬边界后保留** | 仅对 1 个 clip 触发；硬上限 `max_attempts=3`、单任务预算上限、任一 attemp 预算穿线即停并转人工；每次 attempt 的失败归因写进记忆。见 §5.2 | 8–12 → 3 |
| 8 | **Agent 自主"维护 经验教训.md"** | 让 Agent 自由改一个 126KB 的散文文档：会越写越乱、无法检索、无法评估效果，且"维护"没有定义成功 | **改成结构化记忆** | `lesson` 表：`{scope, failure_type, symptom, fix, evidence_revision_id, hit_count}`。下次生成时按 `scope` + 失败类型检索最近 N 条注入提示词。这才叫记忆机制（一面原题） | 3–5 → 2 |
| 9 | **"无限画布 / 多 provider / 三模式"都没有 mock 通道** | v0 完全依赖真实付费 API：开源出去别人跑不起来；演示要联网；每次演示都花钱；无法做回归评测。这是没写出来但最贵的过度设计 | **新增（不是砍）** | `MockProvider`（返回固定产出 + 真实尺寸的假素材）+ 录制回放。仓库零 key 可跑；面试官能本地复现。**这是加分项** | +2 |
| 10 | 文档细节 | `PRD v0.md` 第 9 行链接写坏（`](.\docs\...")` 多了引号），第 15 行代码块边界也不稳。Agent 要"读 skill / 读经验教训"，这些链接就是它的输入 | **顺手修** | v0.2 里统一成相对路径并校验 | — |

### 2.3 总账

**v0 全量 ≈ 70–110 人日 ≈ 14–22 人周**（Yjs 一项就占 15–25 人日）。
一个 6–8 周、1–2 人的团队 = 30–80 人日。**v0 至少是预算的 1.8 倍**，且超支部分全落在最难、最不可控、面试最问不到的地方（第 1、3、4 条）——这是最坏的超支形态。

裁剪后 ≈ **40 人日**（≈ 单人 8 周 / 双人 5–6 周），其中 12 人日花在"面试官最会追问的鲁棒性、成本、评测、可观测"上。

## 3. v0.1 裁剪后的范围

### 3.1 唯一主轴：一条端到端链路

```
原始想法 → 类型化改造（言情→热血 等）
        → 分集大纲 → 分集剧情 → 分镜（clip 列表：时长/景别/台词/参考图指派）
        → 角色三视图/面部特写（图，派生）
        → 每 clip：提示词 → [付费点：用户确认] → 视频草稿(mini 480P)
        → 动作质检(video-motion-review) → 通过 / 归因重写提示词(≤3 次)
        → 正片(720P+) → 镜头墙
```

### 3.2 MVP（必须做完，按"能否演示"排序）

| 优先级 | 功能 | 面试价值 |

### 3.3 明确非目标（写进 README，面试时可当加分项讲）

- 不做 Yjs/CRDT 实时协同编辑（原因见 §2.2 #1，README 保留一段设计取舍）
- 不做自由 DAG 编排引擎、不做插件市场、不做自定义节点 DSL
- 不做多租户、不做计费/发票、不做合规审计、不做邮件通知
- 不做 Celery/Redis/k8s/Kafka：单进程 asyncio 队列 + 数据库 job 表足够
- 不做移动端、不做 i18n、不做主题系统
- 不自研/微调模型、不做本地推理部署（只做推理 API 的适配）

## 4. 轻量设计草案

### 4.1 数据表（8 张，够用）

`user(id, email, pwd_hash, role)` · `project(id, title, owner_id, genre, status)`
`episode(id, project_id, idx, synopsis)` · `clip(id, episode_id, idx, duration_s, shot, dialogue, prompt, ref_asset_ids, status)`
`asset(id, project_id, kind, path, sha256, w, h, dur, source, revision_id)`
`revision(id, target_kind, target_id, prompt, params_json, provider, model, cost, latency_ms, output_asset_id, parent_revision_id)`
`job(id, kind, target_id, state, attempts, budget, cost, error, idem_key, created_at)` — 状态机 `queued→running→waiting_confirm→done|failed|cancelled`
`lesson(id, scope, failure_type, symptom, fix, evidence_revision_id, hit_count, created_at)`

### 4.2 权限矩阵（6 条）

| 权限 \ 角色 | user | lead | admin |
|---|---|---|---|
| 读自己参与的项目 | ✅ | ✅ | ✅ |
| 读他人项目（只读） | ✅ | ✅ | ✅ |
| 建项目 / 邀请成员 | ❌ | ✅ | ❌ |
| 写自己项目（跑生成、改提示词） | ✅ | ✅ | ❌ |
| 配 provider / key | ❌ | ❌ | ✅ |
| 看成本看板（全项目） | ❌ | ✅ | ✅ |

> admin 只读 + 配 key，是刻意的：**超管不能改内容**，这条在面试里可以讲"为什么我不给最高权限写权限"。

### 4.3 Agent 循环（伪代码，收敛条件写死）

```python
async def run_clip(clip, mode):
    for attempt in range(1, MAX_ATTEMPTS + 1):          # 3
        if ctx.cost_used > ctx.budget:                  # 预算熔断
            return Stop("budget_exceeded", attempt)
        prompt = assemble_prompt(clip, lessons=recall(clip, k=3))
        if mode == "default":
            await gate("paid_confirm", preview=prompt)  # 默认模式：付费点停
            if not gate.approved: return Paused
        video = await provider.video(prompt, res=DRAFT)  # 幂等键 = idem(clip, attempt)
        report = await tool.video_motion_review(video)   # vscan + 视觉模型
        if report.verdict == "pass":
            return Ok(attempt)
        lesson = attribute_failure(report)               # 结构化归因
        if not lesson.actionable:                        # 归因不出来就别瞎重试
            return Escalate(lesson)
        save_lesson(lesson); clip.prompt = rewrite(clip.prompt, lesson)
    return Stop("max_attempts", clip)
```

失败分类（决定重试还是重新规划，二面原题）：`schema_invalid` → 重试 1 次 + 修 JSON；`tool_timeout` / `429` / `5xx` → 指数退避重试 2 次；`budget` / `quota` → 不重试，转人工；`content_reject` → 不重试，改提示词；`motion_flag` → 不自动拒绝，只提示（这是 SKILL 的硬规矩）。

## 6. 里程碑（按双人 / 6 周排，单人自动 ×1.6）
