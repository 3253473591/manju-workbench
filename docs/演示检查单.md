# 录屏执行检查单（配合 README「3 分钟演示脚本」）

> README 讲**演什么**，这份讲**怎么不翻车**。每拍三件事：前置状态、操作、失败时怎么说。
> 所有"前置状态"都能被 `scripts/demo_preflight.py` 机器验证 —— 别靠记。

---

## 一、开录前 30 分钟：环境

```powershell
# 1) 数据（只跑一次；幂等，重跑不会多出片段）
python scripts/seed_project.py --source docs\我师父是个普通人 --load --thumbs
python scripts/seed_project.py --source docs\我师父是个普通人 --load --episode 2
python scripts/seed_skills.py

# 2) 后端（录屏口径：全 mock，保证 3 分钟）
$env:DATABASE_URL='mysql+pymysql://root:root@127.0.0.1:3306/manju_dev?charset=utf8mb4'
$env:JWT_SECRET='dev-secret-dev-secret-dev-secret-32'
$env:CSRF_ORIGINS='http://localhost:5173'
$env:MEDIA_ROOT='<仓库>\docs\我师父是个普通人'
$env:VSCAN_PATH='D:\AIGC\ComfyUI-aki-v2\tools\vscan.ps1'   # 不设则动线质检降级 unknown
python -m uvicorn manju.main:app --app-dir apps/api --port 8000

# 3) 前端
cd apps/web; pnpm dev            # http://localhost:5173

# 4) 自检（必须在开录前绿）
python scripts/demo_preflight.py --api http://127.0.0.1:8000
```

彩排（可选，但建议开录前跑一次）：

```powershell
python scripts/demo_rehearsal.py --api http://127.0.0.1:8000
```

它按 9 拍顺序真打一遍接口（9 秒左右），并且**用自己建的临时片段**演打回/重发 —— 不会消耗演示库里的
`review` 片段（打回后回不到 review，是状态机的一部分）。

自检要关心的是**阻断项**（`FAIL`）；`WARN` 可以带着演：

| 检查 | 为什么要它 |
|---|---|
| 迁移到 head（`0009`） | 少一张表就会出现"接口 500"，而且现场看不出原因 |
| 演示项目 active、第一/第二集在 | 跨集复用那一拍依赖两集 |
| `review` 片段 ≥ 1 | **「打回」只在 review 态可点**，这是最容易翻车的一拍 |
| 带产物的 revision ≥ 3 | 版本链/回滚要有东西可回 |
| 跨集复用资产存在 | 1:00 那一拍的证据（库里是 asset 6，被两集引用） |
| Skill 有生效版本 | 2:50 那一拍 |
| 没有通道被停用 | **上一轮演练"止血开关"忘了启用** —— 自检会直接指出来 |
| MEDIA_ROOT 可读 | 否则缩略图全 404，镜头墙一片灰 |

- 浏览器 **1920×1080、缩放 100%**，关书签栏、关通知（Windows 专注助手）。
- 开两个标签页：`localhost:5173` ×2（一个留 owner，一个留给 admin），第三个标签页放 `04-对抗性探针与缺陷记录.md`。

## 三、逐拍执行卡

### 0:00–0:15 定位

| | |
|---|---|
| 前置 | 流水线页、项目《师父是个普通人》、第一集 |
| 操作 | 什么都不点，让页面停 3 s |
| 台词 | "这不是画布工具，是一条**受控的生产链路**：数据是真实成片，每一条生成都能追到钱。" |
| 兜底 | 页面空 → 前端没连上后端（看 devtools Network 有没有 401），不是数据问题 |

### 0:15–0:40 现场建项目 → S1/S2/S3

| | |
|---|---|
| 前置 | 手上没有名为"演示"的项目（有就先归档，别删） |
| 操作 | 「＋项目」→「＋分集」→「运行 S1」→「运行 S2」→「运行 S3」 |
| 台词 | "五环节共用一条代码路径；S3 不是给建议，是**直接写进分镜表**。" |
| 兜底 | S3 返回 409（集里已有片段）→ 这正是设计："重跑分镜会冲掉已出的片"。换一个新集，或者说这句话把 409 讲成卖点 |
| 注意 | 每步等按钮从"运行中…"变回"运行 Sx"再做下一个，别连点 |

### 0:40–1:00 S5 → 用人物卡出图

| | |
|---|---|
| 前置 | 刚跑完 S5，卡片上有「用人物卡出图」 |
| 操作 | 点出图，等缩略图出现（mock 秒出） |
| 台词 | "人物卡只是文本；一致性靠**锚点 + 槽位**，不靠模型记忆。" |
| 兜底 | 503 `PROVIDER_DISABLED` → 讲止血开关（这本身就是加分项），先启用再点；真出图要 40 s，别在录屏里等 |

### 1:00–1:20 跨集复用

| | |
|---|---|
| 前置 | 切回《师父》，**切到第二集** |
| 操作 | 分镜表点「槽位」→ 资产选择里挑第一集用过的人物图 → 保存 |
| 台词 | "资产是**项目级**的，两集共用同一个 `asset_id`，不复制文件。" |
| 兜底 | 资产列表是空的 → 检查槽位弹窗的 kind 过滤（默认图片）；再空就是 seed 没跑 `--thumbs` |

### 1:20–1:45 付费点

| | |
|---|---|
| 前置 | 第二集里选**有提示词**的片段（没有提示词「生成…」是灰的） |
| 操作 | 「生成…」→ 弹窗先读预估，停 2 s →「确认付费」 |
| 台词 | "确认前零计费；出片按 token 记账，不是按秒。" |
| 兜底 | 409 `PROJECT_BUSY`（项目在串行执行）→ "同项目串行，就是这行代码在挡并发烧钱"；等 5 s 再点 |

### 1:45–2:05 质检 + 时间线

| | |
|---|---|
| 前置 | 任务已到终态（弹窗里有 时间线 段） |
| 操作 | 指三色结论，再指时间线的 `claim → provider → asset → review → decision` |
| 台词 | "动线只判'画面在不在动'，内容级判据交视觉模型；**`unknown` 不等于通过**，判不了的片段留在 review。" |
| 兜底 | 全是 `unknown` → 说明降级（没配 `VSCAN_PATH` 或没配视觉 key），把它讲成"判不了就不装懂" |

### 2:05–2:30 打回 → 重发 → 回滚

| | |
|---|---|
| 前置 | 回第一集，找一个 **review** 片段（自检已保证有） |
| 操作 | 「打回」→（改一句提示词）→「重发…」→ 弹窗里点「回滚到此版」 |
| 台词 | "审批绑定在具体 take 上；重发记 `parent_revision_id`；回滚**不写新 revision、不花钱**。" |
| 兜底 | 「打回」是灰的 → 这个片段不是 review 态（approved 不可打回，这是状态机）；换自检清单里的那个 |
| 兜底 | 「重发…」是灰的 → 片段没有提示词，先「槽位」或直接编辑提示词 |

### 2:30–2:50 资产库 + 成本

| | |
|---|---|
| 前置 | 有被引用的资产（自检已保证） |
| 操作 | 「资产库」→ 删一张在用图 → 看 409 面板 → 切「成本台账」→ 按集 |
| 台词 | "资产不级联删：删不掉时告诉你哪个集、哪个片段、哪个槽位在用；成本能按模型/集/片段/天看。" |
| 兜底 | 真删掉了（不该发生）→ 说明这个资产没被引用；换一张，或者直接把 409 面板的 JSON 当证据念 |
| 兜底 | 成本是 0 → 用的是 mock（`unit_price` 为空），讲"mock 记 0，真 provider 的数字在 README 实测表" |

### 2:50–3:10 admin → Skill 试跑 → 发布

| | |
|---|---|
| 前置 | 另一个标签页已登录 admin（`admin@example.com` / `admin12345`） |
| 操作 | 「Skill 维护」→ 改一节 →「试跑」→ 看注入与取舍 →「发布」 |
| 台词 | "知识层受控：没试跑发布不了；试跑只组装、不调用上游。admin 能改规则，改不了内容。" |
| 兜底 | 「发布」灰着 → 这正是单向门，把原因念出来（未试跑 / 试跑目标不匹配） |

## 四、备用拍（时间富余或被打断时）

**备用 A · 止血开关（约 20 s）**

| | |
|---|---|
| 前置 | admin 标签页 |
| 操作 | provider 面板对 `text` 点「停用」（填原因）→ owner 标签页点「运行 S1」→ 看到 503 → admin 点「启用」 |
| 台词 | "闸在**花钱之前**：文本/出图/出片三个入口都埋了；状态存 `runtime_flag` 表，多副本共享。" |
| 收尾 | **必须点回「启用」**，否则下次录制第一步就 503（自检会拦住） |

**备用 B · SSE 跨副本（不占屏幕，口头说）**

> "两个 uvicorn 共享一个 MySQL：B 副本发的事件，A 副本的 SSE 流 ≤0.5 s 补上，靠 `event_log.id` 当 `Last-Event-ID`；
> 单副本仍是进程内直推。真实验过：A 的流收到了 B 的 `id: 6/7 job.updated`。"
