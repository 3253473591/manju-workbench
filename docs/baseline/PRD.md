## 1. 文档效力与目标

本文件为当前 Demo 的业务需求口径，取代此前访谈草稿。为便于本仓库独立分发，
原文中指向作者本机其他文档的相对链接已在此副本中移除，业务内容未作改动。
根目录交接文档作为技术选型与历史资料参考；业务规则以本文件为准，历史模型价格与规格不视为已核实事实。

外部模型 API 的接入点、请求与响应、配置及核验状态集中维护在 [API 对接文档](API对接文档.md)。

面向非技术用户，跑通一集、几个 Clip 的可追溯生产流程：**大纲 → 剧本 → 分镜 → 图片 → 视频**。展示工作流、Agent 编排、版本追溯、资产复用与成本记录，不扩展为完整生产平台。

## 2. 范围

### 本版保留

- 项目管理；每个项目自动创建“第 1 集”和居中的大纲节点。Demo 只开放单集，数据仍保留剧集归属。
- 文本编辑、保存、版本下拉、历史查看、优化分支、专用派生按钮和人物设定。
- Clip 拆分、编辑、补建、排序、屏蔽；角色、场景、道具资产规划及复用。
- 图片与视频的提示词方案、选版、抽卡、屏蔽、媒体预览和来源追溯。
- 单文件文本/图片导入、单源图生图、立绘固定联合派生。
- 无限画布、节点拖动与宽高调整、右侧抽屉、任务反馈。
- 三角色最简权限和登录、生成前费用预估、单价、任务费用明细和项目合计。
- mock/real、服务端幂等、输入快照、媒体落盘与交付核验。

### 暂缓

- 文件夹批量扫描、项目打包迁移（包括专用 API）。
- 多集管理、跨集复制及迁移。
- 0–6 个跨节点对照框，改用版本下拉和历史查看。
- 多参考图图片编辑、视频编辑拼接、完整成片合成、视频文件拖入。
- 充值、余额、支付、财务报表、复杂权限与审批。
- “读取上游重生成”专用入口及 U/A 版本计数切换逻辑。

视频引用多张参考图片仍属于本版，不受图片图生图单源限制影响。

## 3. 权限与模型

| 角色 | 权限 |
|---|---|
| user | 编辑生产内容、提交生成、查看产物与来源；不返回计费字段 |
| manager | 只读查看生产内容、产物、来源、费用明细和项目合计；不编辑或生成 |
| admin | 完整生产及计费权限、用户列表、角色调整、账号启停、必要模型配置 |

开放注册，角色固定为 user。项目由所有用户共享，无项目成员隔离。登录、退出、当前用户读取沿用交接文档最简方案，后端执行权限；manager 的生产只读不妨碍正常登录和退出。

- 只接火山方舟官方接口：豆包负责文本及提示词，Seedream 负责图片，Seedance 负责视频。
- 配置持久化：模型标识、接入点、计价、并发上限、启停和支持规格。
- 产品选项保留图片 lite/pro（默认 lite）、视频 mini/fast/2.5（默认 mini）。这是期望标签，实际型号映射、账号权限、分辨率、时长、参考图上限及 seed 能力在接入时核验，不能把未验证选项伪装可用。
- 文本与提示词调用文本模型；媒体模型选择只作用于媒体生成。
- mock 不发外部模型请求，提供可查看的本地示例结果；real 走真实接口。两者任务和费用能区分，mock 不记为实际支出。

## 4. 对象、版本与分支

- 项目组织共享资产和第 1 集；文本、Clip、媒体方案及结果节点归属该集。项目资产列表导入的文本同样归属第 1 集。
- 资产身份在项目内共享；同名候选各有独立节点和物理文件，不互相覆盖。
- 图片、视频沿用各自类型，区分方案与结果：方案保存提示词；每个结果节点只承载一个产物，也可发起后续优化和抽卡。
- 草稿、不可变历史版本、生成输入快照分开保存。保存或生成前与选中版本比较，实际修改才新增“用户修改”版本；首次保存为 v1，切换历史版本不新增版本。
- 【发送】固定读取当前正文＋本次需求，N 个优化结果分别创建同级节点，各从 v1（AI生成）开始。专用按钮固定读取当前节点保存后的内容生成下一阶段，不做 U/A 判断。
- 历史可查看、复制和载入编辑区；历史或旧连线注释不自动进入新请求。
- 剧本优化分支继承绑定的设定快照、大纲来源和剧集归属；分镜优化分支继承来源剧本版本、设定快照、参考资产列表和剧集归属，同时保留直接优化来源。修改后的内容与引用由用户检查调整。
- 大纲优化分支复制原设定作为可编辑草稿，空设定保持为空。生成剧本前须补齐并确认，正文和设定配套保存。
- 这些继承仅指业务关联，不复制历史版本。同类型手动复制/拖线创建沿用业务关联规则，正文首次保存标为“用户修改”。

## 5. 正常生产流程

### 5.1 大纲与人物设定

- 新项目直接编辑自动创建的大纲；【发送】用于优化或扩写。
- 【人物设定】根据大纲生成设定，先进入草稿区，不改写旧版本。用户检查或修改后，保存或【生成剧本】将“大纲正文＋人物设定”一起保存成不可变版本。
- 保存设定的 AI 来源与执行记录，用户修改参与版本来源标注；切换历史大纲时同时读取其配套设定。
- 设定字段：姓名、身份、性格、外貌特征、发型与头饰、基础服装、服装变体、标志性随身道具；不表示每个字段都要出图。

### 5.2 剧本与分镜

- 大纲【生成剧本】使用保存后的大纲与已确认设定创建剧本候选，记录两者来源；设定为空不能继续。
- 剧本【发送】优化当前正文，并继承绑定设定。修改大纲不自动更新下游；采用新设定须回大纲生成新剧本。
- 剧本【分镜】读取当前保存版本及绑定设定，直接拆为独立 Clip 节点；不先确认整份分镜表。
- Clip 包含编号、总时长、角色、场景；内部镜头包含编号、相对起止时间、画面与动作、景别与运镜、对白与音效。内部镜头不另建节点。
- Clip【发送】优化当前 Clip 并创建同级候选，不以整个剧本替代其正文。重新从剧本拆分则创建新 Clip 节点，旧节点由用户按需屏蔽。
- 允许手建或导入剧本、分镜并先编辑；进入需要设定的生成步骤前，剧本绑定大纲版本与设定，Clip 绑定剧本版本。关联不改写导入正文、不伪造生成记录。
- Clip 可补建和排序；叙事顺序不限制生成或播放次序。

### 5.3 资产规划与复用

- 剧本【人物立绘】汇总其全部未屏蔽关联 Clip 的人物及配套设定；Clip【生成场景】【生成道具】仅规划当前 Clip。
- 三个入口共用查重、规范命名、清单确认及引用回填；确认清单不直接生图。
- 同名资产已有结果或方案时直接复用，不自动重新生成。仅有方案时从原方案抽卡；多个结果保留供用户屏蔽筛选。未命中时才创建图片方案节点及初始 V1。
- 首次角色立绘、场景、道具可走文生图。已有角色新造型从用户选定的具体角色图发起单源图生图，确认新名称，不自动文生图重造角色。
- 不提前创建面部特写、三视图空派生节点。
- 确认清单后将规范资产名回填至 Clip 参考列表。支持添加、替换和移除引用；移除不删除资产。

### 5.4 图片方案与抽卡

- A 是服务端隐藏预设，B 是用户可查看、编辑的描述。A 和完整内部组装/优化文本不通过 API、来源查询或媒体正文返回。
- 普通 A/B 方案由服务端优化 A+B，保存最终生图输入。选版、编辑面向 B；同版再次抽卡复用最终输入。
- 没有产物的文生图方案节点，【发送】基于当前 B、任务上下文和需求优化文生图方案；有源图关联的图生图方案保留源图输入。
- 已有图片结果节点，【发送】使用当前图片、上下文和需求生成图生图方案；每次只允许一张源图。
- 优化只在当前节点追加 V1、V2……，不立即出图；用户选版后主动抽卡。
- 修改 B 后直接抽卡：先保存新的“用户修改”方案，再优化新 A+B、绑定最终输入并生图。内部优化有独立 attempt，不额外增加用户方案版本；同版后续抽卡不再优化。
- 图生图由 Agent 建议目标名，用户抽卡前确认；原名归原候选组，新造型归独立组，不重命名源图。
- N 次抽卡创建 N 个独立同级结果节点，保留方案、源图、目标名、参数、seed；不覆盖旧产物。
- 保留面部特写、三视图、分镜出图、场景、道具预设；角色立绘自动方案基于人物设定生成。

### 5.5 立绘联合派生

- 仅立绘结果节点提供【生成面部特写与三视图】。
- 每次点击以当次选中的立绘为源图，新建两个结果节点并固定各生成 1 张，不使用通用抽卡数量。没有首次填空节点特例，再次点击也不覆盖旧结果。
- 使用下列隐藏固定模板直接生成，不自由改写或人工选版；保留模板方案和输入快照。后续单独重抽复用对应模板和源图快照。

面部特写模板：

> 生成人物脸部超清特写肖像，仅保留头饰与面部，展现面部细节，五官清晰无遮挡，发丝细节完整。背景统一为干净的浅灰底色。

三视图模板：

> 生成角色三视图，从左到右分为三部分：第一部分为正面全身站姿视图，第二部分为纯侧面全身站姿视图，第三部分为背面全身站姿视图，三个视角清晰可辨。背景统一为干净的浅灰底色，三格之间有细白线分隔，人物在每个格子中独立呈现。

### 5.6 视频

- 每次 Clip【生成视频】读取当前保存的 Clip、重新校验当前参考资产，创建新的关联视频方案节点并生成初始方案；按钮本身不出片。
- 方案节点冻结 Clip、参考图片及槽位顺序。节点内【发送】使用这份冻结上下文、当前方案与需求追加版本，不偷偷读取最新 Clip 或重新选图。
- 要用最新内容，回 Clip 再次【生成视频】。旧方案及结果保留；旧方案重抽仍用旧输入。
- 用户修改视频提示词后抽卡，先保存新方案版本。N 次抽卡创建 N 个独立同级结果节点；结果节点继续优化时使用所关联的冻结上下文。
- 每个结果只保存一个视频，落盘后可独立播放，缩略图取第一帧；不拼接整集成片。

## 6. 导入、命名与选图

- 拖入 txt/md/docx 选择大纲、剧本或分镜；jpg/png/jpeg/webp/bmp 选择立绘、面部特写、三视图、场景或道具。保留原文件并创建节点。
- 导入立绘不自动创建派生占位；面部特写和三视图不提供联合派生按钮。
- 名称沿用交接规范，如 `00人物-张三-冬装-三视图`、`01场景-庭院`、`02道具-雨伞`。忽略扩展名、完全匹配，不做语义匹配。
- 图片导入或改名、Clip 参考列表新增或修改，均触发同名匹配并建立引用与连接。
- 改名仅影响当前图片节点，退出旧组并归入新组，解除不再匹配的关系；其他候选、Clip 原需求和历史快照不改写。
- 视频方案生成前，每个所需资产必须恰有一个未屏蔽图片结果，且文件可定位、可读取。方案或未产出节点不计入候选。
- 0 个、多于 1 个候选、命名不合规或文件不可用，均由代码拦截并提示具体资产，不调用视频 Agent，不让 Agent 自选候选。
- 参考图编号、排序和提示词引用来自同一份选择结果，冻结保存。规范名只用于分组，实际文件独立保存。

## 7. 屏蔽与交互

- 新候选默认未屏蔽；不另设采用标记。图片采用由唯一未屏蔽结果推导。
- 屏蔽只影响当前节点，保留内容、历史和媒体，不级联下游；解除不触发任务。屏蔽节点不参与新的派生、规划或批量活动输入，已有下游和冻结输入仍可独立使用。
- 抽屉按节点显示专用按钮、需求框、模型及发送/抽卡。数量表示当前操作的方案数或媒体数，不相乘；实际 API 并发由模型配置控制。
- 随机 seed 各自记录；固定 seed 单次数量为 1。新操作允许相同输入及 seed 再次生成，不做永久内容拦截。
- 画布无限缩放平移，节点可拖动和改宽高；布局不影响内容指纹。新节点按实际尺寸避开旧节点及同批节点，不移动旧节点腾位置。
- 画布/抽屉初始 70%/30%，可在 30%–70% 调整；任务期间相关节点降低不透明度并显示转圈与状态。
- 点击媒体打开抽屉，媒体下方 10px 显示正文区；图片显示 B 和保存，视频显示参考图缩略图与提示词。
- 单行名称回车/失焦确认；多行回车换行，失焦不保存版本或生成。
- 保留双击与拖线创建。拖线仅同级或下一阶段，视频不手动同级拖线；专用按钮和自动抽卡不受该限制。
- 手动图片需确定用途及必要源图；手动视频需关联 Clip，经与 §5.6 相同的校验和上下文冻结后生成方案，不能仅凭图片连线推断完整输入。

## 8. 任务、追溯与计费

- 每次实际模型调用独立 attempt，包括文本、资产规划、提示词优化及媒体。轮询同一供应商任务不新增 attempt；一个文本调用拆出多个 Clip 可共用其来源记录。
- 调用前冻结正文/方案版本、需求、隐藏预设版本、模型规格、参考文件及顺序、内容指纹、依赖边和批次序号。供应商标识、回执、结果随后追加，不覆盖输入。
- logical（用户目标）、physical（执行进程）、delivery（持久化与核验）三层分别保存；不以屏蔽或审美选择代替技术状态。
- 文本须持久化且符合产出结构，媒体须落盘、可定位、可解码。HTTP 200、成功回执或 URL 均不能单独表示交付完成。
- 同一提交的网络重试通过服务端幂等账本复用原任务，不重复付费；已接受的 N 候选批次仍执行 N 次。新用户操作有新提交身份，允许同输入重生成。
- 同一操作执行期间由服务端防重复接受，不仅靠按钮；内容指纹不充当付费提交身份。
- 依赖变化用于追溯，不自动重跑、覆盖产物或将所有连线拼入模型输入。
- 所有调用记录用量和费用，中间的提示词优化也计入。manager/admin 查看预估、单价、明细和项目合计；user 不返回计费字段。
- 按实际执行记录汇总，一个 attempt 被多个 Clip 或节点引用不重复记账。

## 9. Demo 验收

1. 新建项目，填写大纲，生成人物设定并保存。
2. 生成剧本，拆出 2–3 个 Clip，能追溯剧本和设定快照。
3. 确认资产清单，生成或导入图片；同名已有资产能复用。
4. 从立绘联合派生两张图；更换立绘再次操作创建新结果，旧源图记录不变。
5. 屏蔽多余图片候选，唯一有效结果才通过视频方案前置校验。
6. 生成视频方案、选版、主动抽卡；视频落盘后可播放并展示首帧。
7. 修改 Clip 再生成得到新方案节点，旧方案重抽仍使用旧上下文。
8. 查看版本和来源；manager/admin 可看费用，user 不能读取计费或隐藏 A。
9. 刷新后节点、版本、布局、引用及已交付媒体仍可读取。
10. mock 跑通完整链路且无外部模型请求；real 至少验证一个 Clip 从文本到实际图片、视频的完整生成。缺少可用模型或凭证时标注 real 未验收，不用 mock 冒充。

开发阶段落实模型核验、技术字段和调度设计；不恢复暂缓功能，也不引入旧稿 U/A 切换、提前派生占位、首次填空或永久内容去重规则。
